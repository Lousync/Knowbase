# CPU 调度算法

> 《操作系统》· 进程管理

### CPU 调度算法(重要度:★★★★★)

#### 调度的层次、时机与方式

**调度的三个层次**：

| 层次 | 调度对象 | 作用 | 频率 |
|---|---|---|---|
| 高级调度（作业调度） | 从外存后备队列选作业调入内存 | 决定哪些作业进入内存，创建进程 | 低 |
| 中级调度（内存调度） | 从内存中把进程换出到外存 | 缓解内存紧张（挂起/唤醒） | 中 |
| 低级调度（进程调度） | 从就绪队列选进程分配 CPU | 决定哪个进程占用 CPU | 高 |

低级调度（进程调度）是最基本、最频繁的调度，通常所说的调度多指它。

**调度的时机**分需要调度和不需要调度两类。

**需要进行进程调度的情况**：

- 当前进程主动放弃 CPU：运行结束、请求 I/O 阻塞、调用阻塞原语。
- 当前进程被动放弃 CPU：时间片用完、被更高优先级进程抢占。
- 进程创建或终止后，可能重新调度。

**不需要调度的情况**：处理中断过程中、进程在内核态临界区执行时，通常不进行进程调度。

**调度的方式**分两种：

- **非抢占式**：只有当前进程主动让出 CPU 才进行调度。实现简单、开销小，但紧急任务可能长时间得不到处理。
- **抢占式**：当前进程正在执行时，若有更高优先级进程就绪，可强制剥夺其 CPU。响应及时，但调度开销大、需处理抢占竞态。

**闲逛进程**：就绪队列为空时，系统让闲逛进程占用 CPU。闲逛进程的优先级最低，它执行空操作或降低功耗指令，不消耗有效计算。只要有其他进程就绪，闲逛进程立即被抢走 CPU。

**内核级线程与用户级线程的调度**：

**内核级线程**由内核直接调度，每个线程独立分配 CPU，可并行。

**用户级线程**的调度在用户线程库内完成，内核只调度进程（把 CPU 分给进程），进程内部再分配各用户线程。用户级线程调度快，但无法利用多核并行。

#### 调度算法

**先来先服务**：按到达顺序排队，先到的先执行，非抢占。

**优点**：公平、实现简单。

**缺点**：对短作业不利，平均等待时间长，可能出现“长作业饿死短作业”的护航效应。

**短作业优先**：优先执行预计运行时间最短的作业，非抢占。

**优点**：平均等待时间最短。

**缺点**：需预知运行时间，长作业可能**饥饿**（不断被短作业插队）。

**最短剩余时间优先**：短作业优先的抢占版，每当新作业到达，比较其剩余时间与当前作业的剩余时间，若更短则抢占。平均等待时间比短作业优先更短，但切换开销大，长作业仍可能饥饿。

**时间片轮转**：每个进程轮流运行一个时间片（如 20ms），时间片用完强制让出，进入就绪队列队尾。适合交互式系统。时间片太大则退化为先来先服务。太小则切换开销过大。

**优先级调度**：按优先级高低调度，高优先级先运行。分**抢占式**和**非抢占式**。低优先级进程可能**饥饿**，可用**老化**解决，等待越久优先级越高。

**最高响应比优先**：综合了先来先服务和短作业优先。每次调度时选**响应比**最高的进程，兼顾短作业（服务时间短响应比高）和长作业（等待越久响应比越高，不会饥饿），是非抢占算法。

$$
\text{响应比} = \frac{\text{等待时间} + \text{要求服务时间}}{\text{要求服务时间}} = 1 + \frac{\text{等待时间}}{\text{要求服务时间}}
$$

**多级反馈队列**：设置多个就绪队列，优先级从高到低，时间片从短到长。

- 新进程进入最高优先级队列。
- 进程时间片用完未完成，则降到下一级队列。
- 如果执行过程被抢占，则回到当前队列末尾等待。

只有完整用完一次时间片，才会被塞入更低优先级的队列。

**调度算法对比**：

| 算法 | 抢占 | 饥饿 | 特点 |
|---|---|---|---|
| 先来先服务 | 否 | 无（但长作业拖累短作业） | 公平简单 |
| 短作业优先 | 否 | 长作业饥饿 | 需预知运行时间 |
| 最短剩余时间优先 | 是 | 长作业饥饿 | 短作业优先的抢占版 |
| 时间片轮转 | 是 | 无 | 交互式友好 |
| 优先级 | 可/否 | 低优先级饥饿（可老化） | 紧急任务优先 |
| 最高响应比优先 | 否 | 无 | 动态响应比 |
| 多级反馈队列 | 是 | 很少（可老化） | 通用最灵活 |

#### 多处理器调度

**多处理器调度**：多个 CPU 并行执行进程，需要决定哪个进程在哪个 CPU 上运行。**对称多处理器**（SMP）是最常见模式：所有 CPU 地位平等，共享内存和 I/O，每个 CPU 从公共就绪队列取进程，负载由各 CPU 动态平衡。一个进程可在不同 CPU 上迁移执行。

**对称多处理器**（SMP）的特点：

- **对称**：各 CPU 无主从之分。
- **共享**：共享内存、总线、I/O。
- **负载均衡**：每个 CPU 都从公共队列取任务，空闲 CPU 自动取任务。
- **可扩展**：增加 CPU 提升吞吐量，但受共享总线/内存带宽限制。

如果是非对称的多处理器，多个核不共享数据，则需要考虑进程的亲和性，一般每个核有自己的就绪队列，互不共享。

#### 上下文切换

**上下文**是进程在 CPU 上运行时所需的全部状态，包括通用寄存器值、程序计数器、程序状态字、栈指针，以及**进程控制块**中的调度信息。上下文是进程被切换出去后能正确恢复的前提。

**如何切换上下文**：

1. **保存当前进程的上下文**到其进程控制块（保存现场）。
2. **更新当前进程的进程控制块**：状态改为就绪/阻塞，加入相应队列。
3. **选择下一个进程**：从就绪队列取。
4. **更新新进程的进程控制块**：状态改为运行。
5. **恢复新进程的上下文**：从进程控制块装入寄存器、程序计数器、程序状态字（恢复现场）。

**切换的时机**：发生进程调度时（时间片到、被抢占、主动让出 CPU 等）。

**切换的消耗**：上下文切换是纯开销，不完成任何有用工作，需要保存和恢复寄存器、更新进程控制块、可能刷新快表，消耗 CPU 时间。频繁切换（如时间片过小）会导致大量时间浪费在切换上，降低系统吞吐量。

> ⚠️ **中断会不会引发进程调度**
>
> 一般认为中断发生时并不发生进程调度（上下文切换）：中断处理程序只在当前进程的内核态执行，保存和恢复的是同一进程的现场。只有当进程被阻塞（主动请求 I/O 等）或从中断返回时系统发现更高优先级进程就绪，才会触发真正的进程调度与上下文切换。
