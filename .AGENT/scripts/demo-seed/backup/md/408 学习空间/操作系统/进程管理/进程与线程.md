# 进程与线程

> 《操作系统》· 进程管理

### 进程的概念与状态(重要度:★★★★★)

#### 进程与 PCB

**进程**是程序的一次执行过程，是系统进行资源分配和调度的基本单位。进程实体由程序段、数据段、进程控制块（PCB）三部分组成。其中 PCB 是进程存在的唯一标志，系统通过 PCB 感知进程的存在，没有 PCB 的进程在系统中不存在。

**进程的特征**：

- **动态性**：进程是程序的一次执行，有创建、运行、消亡的生命周期，程序是静态的。
- **并发性**：多个进程可同时存在于内存并交替执行。
- **独立性**：进程是独立获得资源、独立调度的基本单位。
- **异步性**：进程按各自不可预知的速度推进。
- **结构性**：进程由程序段、数据段、PCB 三部分组成。

**PCB 的作用**：

- 作为独立运行基本单位的标志。
- 实现间断性运行：进程暂停时保存现场，恢复时根据 PCB 恢复。
- 提供进程管理所需的信息（调度、同步、通信）。
- 提供进程调度所需的信息（状态、优先级）。
- 实现系统对进程的控制（挂起、唤醒）。

![示意图](attachment://vault/6238d65d-3a4f-4f83-a758-6ceae59f3890/kb-os-process-1-4.svg)

> 💡 **PCB 常驻内存**
>
> 所有未被销毁的进程，其 PCB 都常驻内存。即使进程被挂起到外存，PCB 仍留在内存中。系统依靠 PCB 感知、管理进程，PCB 一旦撤销，进程就不存在了。

#### 进程状态的转换

进程在其生命周期内会经历多种状态：

- **创建态**：进程正在被创建，PCB 已建立但资源未就绪。
- **就绪态**：万事俱备只欠 CPU，等待被调度。
- **运行态**：占用 CPU 执行。
- **阻塞态**：等待某事件，如 I/O 完成。
- **终止态**：进程执行结束，等待回收。

引入**挂起**后，还有：

- **就绪挂起**：就绪进程被调到外存。
- **阻塞挂起**：阻塞进程被调到外存。

![示意图](attachment://vault/6238d65d-3a4f-4f83-a758-6ceae59f3890/kb-os-process-2-3.svg)

> 💡 **阻塞必须经过就绪**
>
> 阻塞态进程等待的事件发生后，先进入就绪态排队，等被调度后才能运行。不存在"阻塞直接转运行"。

#### 进程间的通信

进程间通信（IPC）是进程之间交换数据的方式。常用方法：共享存储、消息传递、管道通信、信号。

**共享存储**：多个进程共享一块内存区域，数据直接在共享空间读写，速度最快。但需要进程自身实现**同步互斥**（如用信号量控制访问），否则数据不一致。共享分两种：

- **基于数据结构的共享**：如共享一个数组。
- **基于存储区的共享**：共享一整块内存。

**消息传递**：进程以**消息**为单位交换数据，由内核提供发送原语 send 和接收原语 receive。消息传递分两种：

- **直接通信**：消息直接发到对方邮箱/进程。
- **间接通信**：通过中间信箱转发。

消息传递无需共享空间，适合分布式环境。

**管道通信**：通过**管道**（一种共享文件/缓冲区）连接两个进程，一个写、一个读，数据先进先出。管道容量有限，写满阻塞写者，读空阻塞读者。

**信号**：用于进程间**传递通知**，不传输大量数据，如 SIGINT（Ctrl+C 中断）、SIGKILL（终止进程）、SIGCHLD（子进程结束通知父进程）。信号由内核产生并递送给进程，进程可处理、忽略或阻塞。

**四种 IPC 方式对比**：

| 方式 | 数据量 | 同步机制 | 适合场景 |
|---|---|---|---|
| 共享存储 | 大 | 需自己加锁 | 大量数据、同机进程 |
| 消息传递 | 中 | 内核协调 | 分布式、需要结构化 |
| 管道通信 | 中 | 内核同步（阻塞） | 有血缘关系进程、流式数据 |
| 信号 | 小（通知） | 内核异步递送 | 通知事件、异常处理 |

### 线程(重要度:★★★★)

#### 线程

**线程**是进程内的一条执行流，是 CPU 调度的基本单位。

一个进程可以包含多个线程，线程共享进程的地址空间和资源，但每个线程有自己的程序计数器（PC）、寄存器组、栈。引入线程的目的是减少程序并发执行时的时空开销，提高系统的并发程度。

**进程与线程的区别**：

| 对比 | 进程 | 线程 |
|---|---|---|
| 组成 | 程序段 + 数据段 + PCB | TCB + 自己的栈/寄存器 |
| 资源分配 | 系统资源分配的基本单位 | 基本不拥有资源（只占少量） |
| 调度 | 早期以进程为调度单位 | CPU 调度的基本单位 |
| 地址空间 | 每个进程独立地址空间 | 同一进程的线程共享地址空间 |
| 共享情况 | 不涉及 | 共享进程内的堆、代码、数据等，但各自栈、寄存器、PC 不共享 |
| 不共享 | 不涉及 | 各自的栈、寄存器、PC |
| 开销 | 创建/切换开销大 | 创建/切换开销小 |
| 独立性 | 独立、互不影响 | 一个线程崩溃可能导致整个进程崩溃 |

#### 多线程模型

根据用户级线程与内核级线程的关系，多线程模型分三种：

- **一对一模型**：每个用户线程对应一个内核线程。
- **多对一模型**：多个用户线程映射到一个内核线程。
- **多对多模型**：多个用户线程映射到多个内核线程。

**三种多线程模型对比**：

| 模型 | 并发性 | 阻塞影响 | 创建开销 | 适用 |
|---|---|---|---|---|
| 一对一 | 高，可多核并行 | 一个线程阻塞不影响其他 | 大（每线程一个内核线程） | 高性能计算 |
| 多对一 | 低，只能单核 | 一个线程阻塞整个进程阻塞 | 小（用户态管理） | 简单应用 |
| 多对多 | 高，可多核并行 | 一个阻塞不影响其他 | 适中 | 现代系统主流 |

#### 用户级线程与内核级线程

**用户级线程（ULT）**：线程的管理（创建、调度、撤销）由用户程序通过线程库完成，内核无感知，切换不涉及内核、速度快，但不能利用多核并行（一个线程阻塞会导致整个进程阻塞）。

**内核级线程（KLT）**：线程的管理由内核完成，内核感知每个线程，可独立调度到不同 CPU 上并行，一个线程阻塞不影响其他线程，但切换需要内核介入、开销大。

**用户级线程与内核级线程对比**：

| 对比 | 用户级线程 | 内核级线程 |
|---|---|---|
| 管理方 | 用户线程库 | 操作系统内核 |
| 内核感知 | 内核无感知 | 内核感知 |
| 切换开销 | 小（不进入内核） | 大（需内核切换） |
| 多核并行 | 不能利用 | 可利用 |
| 阻塞影响 | 一个阻塞整个进程阻塞 | 一个阻塞不影响其他 |
| 代表 | POSIX Pthreads（用户模式） | Windows、Linux 线程 |
