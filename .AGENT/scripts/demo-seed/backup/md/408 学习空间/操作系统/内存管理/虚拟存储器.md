# 虚拟存储器

> 《操作系统》· 内存管理

### 虚拟存储器的基本思想(重要度:★★★★)

#### 虚拟存储器的基本思想

**虚拟存储器**在物理内存与磁盘之间建立抽象的、扩展的内存空间，使进程能运行在比实际主存大的地址空间。

**逻辑地址空间与物理内存解耦**：程序看到连续完整的虚拟地址空间，虚拟地址通过页表和 TLB 映射到物理内存，不直接对应物理位置。

> 💡 **解耦带来的收益**
>
> 有限的物理内存可以支持更大的虚拟地址空间，同时每个进程有自己的页表，实现进程间隔离与保护，还能让多个进程共享同一物理页。

---

### 虚拟存储器的实现(重要度:★★★★★)

#### 页式虚拟存储与地址结构

**页式虚拟存储**把虚拟地址空间和物理地址空间都划分为大小固定的页。程序运行时按需加载部分页面到内存，其余页面留在磁盘。

**虚拟地址**（VA）分为**虚拟页号**（VPN）和**页内偏移**；**物理地址**（PA）分为**物理页号**（PPN）和**页内偏移**。

#### 段式与段页式

**段式虚拟存储**按程序的逻辑结构分段，每段独立编址，便于共享和保护，但段长不固定、管理复杂。

**段页式**先按逻辑分段，段内再分页，兼顾段的共享保护与页的固定管理，但需要两级查表，开销更大。

| 特点 | 页式 | 段式 |
|---|---|---|
| 划分单位 | 固定大小页 | 不定长段（按逻辑结构分段） |
| 地址空间 | 一维（线性） | 二维（段号+段内偏移） |
| 程序员视角 | 对程序员透明，无需关心分页 | 程序员可见，按段编程容易 |
| 共享与保护 | 较难 | 方便（按段保护），更安全 |
| 碎片 | 无外部碎片，但有内部碎片 | 有外部碎片，无内部碎片 |
| 管理复杂度 | 简单 | 复杂 |

#### 地址转换

**MMU**（内存管理单元）负责虚拟地址到物理地址的转换，同时实施内存保护，根据页表中的保护位控制读、写、执行权限。

最后用 PPN 和页内偏移拼出物理地址，再访问 Cache 或主存。

**页表**将虚拟页号映射为物理页号，每个进程有自己的页表，存放在内核空间。**页表项**（PTE）包含物理页号、有效位、修改位、访问位、保护位等字段。

**多级页表的优点**：单级页表为 4GB 虚拟地址空间配 4KB 页面需常驻 4MB 页表，而程序实际只用一小部分地址空间；多级页表按需分配下级页表，大幅节省内存。

**缺点**：访问一个页表项需要多次访存（每级一次），翻译速度变慢，常配合 TLB 缓存以抵消开销。

**地址翻译过程**：

1. 从 VA 提取 VPN，先查 TLB。
2. TLB 命中：直接得到 PPN。
3. TLB 未命中：查页表。页表命中得到 PPN 并更新 TLB；页表未命中则触发缺页中断。


#### TLB

**TLB**（快表）是 MMU 中的高速缓存，保存最近使用的虚拟页号到物理页号的映射，加速地址翻译。TLB 用 **SRAM** 实现，因为它在 CPU 内部、要求高速访问，且容量小（几十到几百项），不需要 DRAM 那样的大容量和刷新。

页表存于内存，每次地址翻译至少要访问一次内存，开销大。TLB 离 CPU 近、速度快，命中后免去查页表。

TLB 与 Cache 类似，也有**直接映射、组相联、全相联**三种方式。TLB 用 VPN 查找，Cache 用主存块号查找。

> 💡 **TLB 与 Cache 的分工**
>
> TLB 在地址翻译阶段把 VPN 换成 PPN，Cache 在物理访存阶段缓存主存块。两者都是硬件高速缓存，作用场景不同。

#### 主存访问流程与页面置换

访问的页面不在物理内存时触发**缺页中断**（也称缺页异常）：MMU 发现页表项有效位为 0，交由操作系统内核处理。

**页故障地址**（page fault address）是触发缺页中断的那条访存指令要访问的**虚拟地址**。缺页发生时，硬件把这个地址写入专门寄存器（如 x86 的 **CR2**）。

缺页处理程序据此定位不在内存的虚拟页：从磁盘调入该页、更新页表与 TLB，再重新执行触发缺页的指令。

![缺页中断完整流程：CPU 发虚拟地址 → 查 TLB → 查页表有效位 → 触发缺页异常 → 换页/装入页框 → 更新页表/TLB → 重新执行本条指令 → 形成物理地址 → 访问 Cache](图片资源缺失:undefined)

内存已满需要调入新页时，必须**置换**一个旧页。常用**页面置换算法**：

- **OPT**（最优置换）：淘汰以后最久不用的页，理论最优，不可实现。
- **FIFO**（先进先出）：可能产生 Belady 异常，增加页框反而缺页更多。
- **LRU**（最近最久未使用）：性能好，但需硬件支持、开销大。
- **CLOCK**（时钟置换）：用访问位近似 LRU，实用。

| 算法 | 思想 | 优点 | 缺点 |
|---|---|---|---|
| 最优置换（OPT） | 淘汰未来最久不使用 | 缺页率最低 | 需预知未来，不可实现 |
| 先进先出（FIFO） | 淘汰最先进入 | 实现简单 | 可能 Belady 异常 |
| 最近最久未使用（LRU） | 淘汰最久未使用 | 性能好 | 硬件开销大 |
| 时钟置换（CLOCK） | 访问位轮转 | 折中、实用 | 近似 LRU |

**页框分配方式**：
- **固定分配**：平均分配、按比例分配、按优先级分配
- **可变分配**：根据进程缺页率动态调整页框数

**置换范围**：
- **局部置换**：只在本进程的页框内选淘汰页
- **全局置换**：从所有进程的页框中选，可能换出其他进程的页

常见组合：

- 固定分配 + 局部置换。
- 可变分配 + 全局置换。
- 可变分配 + 局部置换。

**页框回收**：进程撤销时，系统回收其全部页框，加入空闲页框链表。

进程执行中因缺页调入新页时，也可能回收被置换页的页框：干净页直接释放，脏页需先写回磁盘。

> 💡 **固定 vs 可变分配**
>
> 固定分配页框数不变，简单但难适应进程需求变化；可变分配按需调整，利用率高但管理复杂。局部置换与全局置换的区别在于从哪些进程的页框中选淘汰页。

#### 内存映射文件

**内存映射文件**（mmap）把磁盘文件的一部分直接映射到进程的虚拟地址空间，进程通过访问内存来读写文件，无需显式的 read/write 系统调用。操作系统按需从磁盘调入对应页，修改的页在写回时同步到磁盘。

**优点**：读写文件像访问内存一样高效，多个进程可共享同一文件映射，节省内存。

**缺点**：映射的文件大小受虚拟地址空间限制，小文件映射可能不如传统 I/O 高效。

mmap 常用于加载可执行文件、共享库、大数据文件处理。
