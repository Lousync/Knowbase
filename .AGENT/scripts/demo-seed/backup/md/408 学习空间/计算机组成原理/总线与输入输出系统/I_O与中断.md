# I/O与中断

> 《计算机组成原理》· 总线与输入输出系统

### I/O(重要度:★★★★★)

#### I/O 接口与端口

**I/O 接口**是连接主机与外设的桥梁，负责速度匹配、数据格式转换、控制和定时、错误与状态检测。设备控制器更强调控制逻辑，I/O 接口更强调连接角色，通常可视为同一实体的不同视角。

**I/O 端口**是接口电路中 CPU 可直接访问的寄存器，分三类：

- **数据端口**：存放待传输数据。
- **状态端口**：存放忙/闲等状态，只读。
- **控制端口**：接收控制命令，只写。

**统一编址**（MMIO）：I/O 端口映射到内存地址空间，用**普通内存指令**访问。编程方便，不占用独立的 I/O 地址空间。

**独立编址**（PMIO）：I/O 端口地址空间与内存分离，必须用 IN/OUT 指令访问。

> 💡 **现代架构偏好 MMIO**
>
> ARM、RISC-V 及多数 PCIe 设备用 MMIO；传统 x86 为兼容老设备，同时支持 MMIO 和 PMIO。

| | 数据线 | 控制线 | 状态线 |
|---|---|---|---|
| 方向 | 双向 | 主机 → 外设（输出） | 外设 → 主机（输入） |
| 作用 | 在接口与设备间传输数据 | 主机向设备发送控制命令（启动、停止、选择） | 设备向主机报告状态（忙/闲、就绪、出错） |
| 对应端口 | 数据端口 | 控制端口 | 状态端口 |
| 读 / 写 | 可读可写 | 只写 | 只读 |

#### 四种 I/O 控制方式

| I/O 方式 | CPU 负责数据搬运 | CPU 等待设备 | 特点 |
|----------|----------------|-------------|------|
| 程序查询 | 是 | 是（不断轮询） | 实现最简单，CPU 利用率最低 |
| 程序中断 | 是 | 否 | 设备完成后主动通知 CPU |
| DMA | 否（DMA 控制器） | 否 | CPU 只负责初始化，效率高 |
| 通道 | 否（通道负责） | 否 | 大型机使用，可管理多个设备 |

**程序查询方式**：CPU 不断轮询设备状态寄存器，设备就绪才传输数据。实现简单，但 CPU 大量时间在等待和轮询，利用率最低。

**程序中断方式**：设备准备好后触发中断通知 CPU，CPU 暂停当前任务响应中断，进入中断服务程序搬运数据。CPU 不需要一直等待，但每次中断只能传输少量数据，高速设备下中断开销大。

**DMA 方式**：DMA 控制器让数据直接在 I/O 接口和主存之间传输，CPU 只在传输前配置参数、传输结束后接收完成中断，不参与数据搬运。适合高速、大批量数据传输。

**通道方式**：通道是专门负责 I/O 的处理器（I/O 处理机），能独立执行通道程序。CPU 只需下达一次 I/O 命令，通道负责整个 I/O 过程，可同时管理多个设备，用于大型机。

> ⚠️ **CPU 参与程度逐渐降低**
>
> 程序查询：CPU 等待+搬运；程序中断：CPU 不等待但搬运；DMA：CPU 只初始化；通道：CPU 只下达任务。

#### DMA 方式的细节

**DMA 控制器**组成：

- DR：数据寄存器。
- MAR：内存地址寄存器，每传一次自动更新。
- DC：数据计数器，记录剩余数据量。
- CR：命令/状态寄存器。

DMA 传输分三个阶段：

- **预处理**：CPU 配置 DMA 参数，包括主存地址、传输长度、方向。
- **数据传输**：DMA 在 I/O 与主存间直接搬运，修改 MAR 和 DC。
- **后处理**：DMA 发完成中断，CPU 检查结果。

**DMA 与 CPU 争用总线**的处理方式：

- **总线独占**：DMA 独占总线，CPU 无法访存。
- **周期挪用**：DMA 逐个窃取总线周期，CPU 空闲时仍可访存。
- **分时多路复用**：按预定时钟周期轮流使用。

| 争用方式 | 总线使用权 | 对 CPU 访存的影响 | 传输效率 | 适用场景 |
|---|---|---|---|---|
| 总线独占 | DMA 独占总线 | CPU 完全无法访存，暂停工作 | 最高（整块连续传） | 传输周期极短、要求一次完成的场合 |
| 周期挪用 | DMA 每传一次窃用一个总线周期 | CPU 只在被窃取的周期暂停，其余时间正常访存 | 较高 | 最常用，兼顾 DMA 与 CPU |
| 分时多路复用 | CPU 与 DMA 按固定时间片轮流 | CPU 按预定节拍访存，受时间片限制 | 中等 | 传输不太紧急、需保证 CPU 连续性的场合 |

当 CPU 和 DMA 都需要访问主存时，**DMA 优先**：磁盘一旦开始读写必须按时完成传送，否则缓冲区数据丢失。DMA 传输过程中，CPU 只负责初始化、检查结果，不参与数据搬运。

> 💡 **DMA 数据是否经过 CPU**
>
> DMA 数据绕过 CPU 的寄存器和执行单元，但仍经过 CPU 芯片内部的互连结构和内存控制器，只是不占用 CPU 核心计算资源。

#### I/O 层次与设备分类

**I/O 软件层次**从上到下：

1. **用户层 I/O 软件**：系统调用、printf/scanf。
2. **设备独立性软件**：设备命名、缓冲、逻辑设备到物理设备的映射。
3. **设备驱动程序**：与设备硬件直接交互，处理设备寄存器。
4. **中断处理程序**：响应设备中断。
5. **硬件**。

![示意图](attachment://vault/8a977dfe-63e0-48d5-a6c3-73ca3f7ec735/kb-co-io-method-4-5.svg)

**用户层 I/O 软件**：提供**系统调用接口**（read、write、open 等）和**库函数**（printf、scanf、fread 等），是应用与 I/O 系统打交道的入口。用户程序通过系统调用请求 I/O，不直接接触设备。

**设备独立性软件**（设备无关层）实现：

- **设备命名**：用逻辑设备名统一命名。
- **设备保护**：访问权限。
- **缓冲管理**。
- **设备分配与回收**。
- **逻辑设备到物理设备的映射**。
- **SPOOLing**。

它向用户提供统一的设备访问方式，屏蔽不同设备的差异，使应用与具体设备无关。

**设备驱动程序**：每个设备类型对应一个驱动程序，它是**唯一直接操作设备硬件**（设备控制器寄存器）的软件层。驱动程序把设备独立性软件传来的逻辑 I/O 命令翻译成具体设备的命令序列，并处理设备返回的状态。驱动程序出错可能导致系统崩溃。

**中断处理程序**：设备完成 I/O 后发中断，中断处理程序按以下顺序响应：

1. 保存现场。
2. 读取设备状态。
3. 完成数据传输或唤醒等待进程。
4. 恢复现场。

中断处理程序与设备驱动程序紧密配合，通常视为一层。

**阻塞 I/O**：进程发起 I/O 后阻塞等待，直到数据就绪才返回。期间进程不占 CPU，实现简单但效率低。

**非阻塞 I/O**：进程发起 I/O 后立即返回，可继续执行其他工作，之后轮询或由事件通知结果。效率高但编程复杂（如 select/poll、epoll、异步 I/O）。

| 对比 | 阻塞 I/O | 非阻塞 I/O |
|---|---|---|
| 进程是否等待 | 是，阻塞直到完成 | 否，立即返回 |
| CPU 利用率 | 等待时不占 CPU | 可以返回本进程继续做其他事 |
| 实现复杂度 | 简单 | 复杂（轮询/回调） |
| 适用 | 简单程序 | 高并发、高性能场景 |

### 中断与异常(重要度:★★★★★)

#### 中断的概念与分类

**中断**是 CPU 在正常执行程序过程中，由外部设备或软件指令触发的事件，促使 CPU 暂停当前执行，转而响应处理该事件。

按来源，中断分为**外部中断**和**异常**两大类。

**外部中断**来自 CPU 外部（外设、时钟、外部信号），与当前执行的指令无关。

**异常**（内中断）由 CPU 内部或当前指令触发，按严重程度和处理方式又分为**故障**（fault）、**终止**（abort）和**自陷**（trap）三类。

| 类别 | 触发条件 | 检测时机 | 处理完后回到哪 | 是否可屏蔽 | 典型例子 |
|---|---|---|---|---|---|
| 外部中断 | 外部设备请求（I/O、定时器、时钟） | 当前指令执行完后检测 | 回到下一条指令 | 可屏蔽（IRQ）/ 不可屏蔽（NMI） | 键盘输入、定时器到时、网络包到达 |
| 故障 fault | CPU 内部/当前指令引发 | 指令执行过程中检测 | 回到**当前指令**重新执行 | 不可屏蔽 | 缺页、除零、越权访问、非法指令 |
| 终止 abort | 硬件严重错误 | 指令执行过程中检测 | **不返回**，程序无法恢复 | 不可屏蔽 | 内存校验错、总线故障、硬件错误 |
| 自陷 trap | 程序**主动**执行陷阱指令（如 INT n、系统调用） | 指令执行后（或主动触发） | 回到下一条指令 | 不可屏蔽 | 系统调用、调试断点、INT 指令 |

**外部中断**按可屏蔽性分：

- **可屏蔽中断**（IRQ）：可通过屏蔽字或 IF 标志暂时禁止，通常是普通外设中断。
- **不可屏蔽中断**（NMI）：无法屏蔽，用于系统级错误（电源故障、内存校验错误），优先级最高。

**常见的外部中断**：键盘输入、鼠标移动、定时器到时、网络数据包到达、磁盘 I/O 完成、打印机就绪。

**常见的异常**：

- 故障：缺页、除零、非法指令、越权访问、溢出。
- 终止：内存校验错误、总线错误。
- 自陷：系统调用 INT、调试断点。

> ⚠️ **故障 vs 自陷 vs 终止**
>
> 故障处理完回到当前指令重做；自陷处理完回到下一条指令；终止无法恢复不返回。检测时机：故障和终止在指令执行中，自陷在指令执行后，外部中断在指令执行完后。

#### 中断处理流程

完整的中断处理过程：中断触发 → 中断识别 → 屏蔽处理 → 保存断点 → 中断服务寻址 → 执行中断服务程序 → 中断返回。

**保存断点**由硬件自动完成（**中断隐指令**），保存 PC、PSW 等，使中断结束后能恢复下一条指令的执行。

**保存现场**在中断服务程序中由软件完成，保存程序使用的通用寄存器。

**中断向量表**（IVT）把中断号映射到中断处理程序入口地址。中断发生时，CPU 用中断号作为表下标找到中断向量，跳转到对应处理程序。

**中断向量**是中断服务程序入口的**地址**。

中断发生时，CPU 用中断号作为下标，在**中断向量表**（IVT）中找到对应表项，表项里存的就是该中断的中断向量（一个内存地址），CPU 据此跳转到中断服务程序。

![示意图](attachment://vault/8a977dfe-63e0-48d5-a6c3-73ca3f7ec735/kb-co-interrupt-2-8.svg)

> ⚠️ **断点 vs 现场**
>
> 断点是中断前执行的位置（PC、PSW），由硬件保存；现场是通用寄存器的内容，由中断服务程序用软件保存。做题时注意区分两者。

#### 中断嵌套与中断屏蔽

**单重中断**：CPU 在执行中断服务程序时不响应任何新中断请求，所有中断串行处理。实现简单，进入 ISR 后关中断，处理完再开。

**多重中断**（中断嵌套）：允许更高优先级的中断打断当前 ISR。需要两个条件：

1. 进入 ISR 后重新开中断（IF=1）。
2. 只有更高优先级的中断才能打断。

**中断屏蔽字**实现多重中断的优先级控制：每个中断源对应一个屏蔽触发器，1 表示屏蔽、0 表示允许。执行某个 ISR 时，把比它优先级低的源屏蔽，让更高优先级的源能打断。

例如四个中断源的**响应优先级**为 A > B > C > D，通过屏蔽字把**处理优先级**调整为 A > D > C > B。执行 B 的 ISR 时装入 0100，只屏蔽 B 自身，C、D 仍可打断 B；若 C、D 同时请求，先按响应优先级进入 C，随后 D 还能继续打断 C。

> 💡 **响应顺序与处理顺序要分开**
>
> 中断屏蔽字不改变硬件的响应优先级，但会改变中断能否嵌套，从而改变实际处理完成的先后顺序。单重中断直接关中断，无需屏蔽字。

#### 用户态与内核态

CPU 执行程序时处于两种状态之一：**内核态**（核心态/管态）和**用户态**（目态）。

内核态可执行所有指令、访问所有资源；用户态只能执行非特权指令、访问受限资源。两者由**程序状态字 PSW** 中的状态位区分（如 0 用户态、1 内核态）。

**特权指令**只能在内核态执行，如：

- I/O 指令（IN/OUT，直接访问外设）。
- 置中断屏蔽（开/关中断指令 CLI/STI）。
- 清内存、置存储保护键。
- 修改 PSW（切换用户态/内核态）。
- 停机指令（HLT）。
- 加载/重置定时器。
- 修改页表/段表基址寄存器（如 LTR、LGDT）。

**非特权指令**在用户态即可执行，如算术运算、取数存数、转移指令、访存（非 I/O）。

用户态执行特权指令会触发保护异常，由系统捕获处理。

| 对比 | 用户态 | 内核态 |
|---|---|---|
| 权限 | 低，只能执行非特权指令 | 高，可执行全部指令 |
| 资源访问 | 受限（不能直接访问硬件/内核数据） | 全部资源 |
| 代表程序 | 用户应用程序 | 操作系统内核 |
| 状态位 | PSW 用户态 | PSW 内核态 |

**用户态与内核态的转换**：

- 用户态 → 内核态：通过**中断/异常/陷入**（系统调用）触发，是唯一的切换途径。
- 内核态 → 用户态：通过中断返回（IRET）或特权指令（如修改 PSW）实现。

每次系统调用、每次中断都伴随状态切换，频繁切换会带来性能开销。

#### 系统调用

**系统调用**是操作系统提供给应用程序使用内核服务的**接口**。应用程序在**用户态**通过**陷入指令**（trap，如 x86 的 INT n、syscall）请求内核服务，CPU 切换到**内核态**执行对应的系统调用处理程序，完成后返回用户态。

系统调用是用户态进入内核态的主要途径之一。

**系统调用指令的特点**：

1. 在用户态执行，执行后把控制交给内核，进入内核态。
2. 指令本身不完成具体功能，只是**陷入内核**、触发状态切换的入口。
3. 具有原子性，执行过程不可被打断。

常见系统调用：进程管理（fork/exec）、内存管理（brk/mmap）、文件操作（open/read/write）、设备管理（read/write）、信息维护（getpid/time）。

**子程序调用**（过程调用）在**用户态**内完成，不切换状态，通过 CALL/RET 跳转。被调函数与调用者共享同一地址空间，无权限提升。

**系统调用**需要**切换到内核态**，涉及状态保存与恢复、开销大，能访问内核资源。

| 对比 | 系统调用 | 子程序调用 |
|---|---|---|
| 状态 | 用户态 → 内核态 | 全程用户态 |
| 触发 | 陷入指令（INT/syscall） | CALL 指令 |
| 权限 | 可访问内核资源 | 只能在用户态地址空间 |
| 开销 | 大（含状态切换） | 小 |
| 返回 | 中断返回，恢复现场 | RET 返回 |
| 服务对象 | 操作系统内核服务 | 用户程序内的函数 |

**系统调用前必须先设置参数**：用户程序执行陷入指令前，把**系统调用号**和**所需参数**放入约定位置（寄存器/参数表/栈），然后才执行陷入指令。

原因：

1. 陷入指令只负责"陷入内核"，本身不携带信息，内核无法知道用户要调用哪个服务、传了什么数据。
2. 参数设置完成后，陷入指令才能把 CPU 切换到内核态，内核通过寄存器中的**系统调用号**查系统调用表定位处理程序，再读取参数执行。
3. 参数在用户态先设置好，保证陷入后内核能立即获得完整信息。

**系统调用的参数传递方法**：

1. **寄存器传递**：把参数放在通用寄存器中，适合参数少的情况。
2. **参数表传递**：把参数放入内存中的一张参数表，寄存器只存放参数表的首地址，适合参数多的情况。
3. **栈传递**：利用调用栈传递参数。

系统调用号也放在寄存器中，内核据此查表定位处理程序。
