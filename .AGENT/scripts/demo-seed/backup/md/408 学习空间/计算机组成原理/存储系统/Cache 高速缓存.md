# Cache 高速缓存

> 《计算机组成原理》· 存储系统

### Cache 的基本概念(重要度:★★★★★)

#### 时间局部性原理与空间局部性原理

**Cache** 是位于 CPU 与主存之间的高速小容量存储器，保存主存中部分内容的副本。

CPU 访问数据时先查 Cache：命中就直接使用；未命中才访问主存，并把所在主存块调入 Cache。

Cache 能加速依赖**局部性原理**。**时间局部性**指刚访问过的数据很可能很快再被访问，常见于循环中的计数器和频繁读取的变量。

**空间局部性**指访问某个数据后，其附近的数据也很快会被访问，常见于数组等连续存储结构的遍历。

#### Cache行

**缓存块**（Cache block）是 Cache 与主存交换数据的基本单元。

**主存块**是主存中与缓存块大小一致的存储区域，主存与 Cache 之间的数据置换以块为单位。

**Cache 行**（Cache line）包含标记字段和主存块。

**块内偏移**是数据在块内的位置，找到块后用它定位具体字节。

**块大小**决定块内偏移的位数。例如块大小为 1KB，则 $1KB = 2^{10}$，块内偏移占 10 位。典型缓存块大小是 32、64、128 字节。

![示意图](attachment://vault/e04abedf-15cd-4dc3-87f5-e301acd6fac2/kb-co-cache-structure-5.svg)

> 💡 **与页式存储的类比**
>
> Cache 块与主存块的对应关系类似页式存储中的页与页框：主存和 Cache 按块对应，置换以块为基本单位。

#### Cache 的标记字段

Cache 存储内容分**数据**和**标记字段**两部分。

标记字段包括：

- **有效位**（valid）：标识该行是否存有有效数据。
- **脏位**（dirty）：标识该块是否被修改过。
- **替换位**（reference）：记录访问信息，服务于替换算法。
- **标记**（tag）：与地址中的 tag 比较，判断是否命中。

#### Cache 的地址结构

给定**物理地址**访问 Cache，地址划分为三部分：**标记（tag）、块匹配字段、块内地址**。

**块内地址**确定数据在块内的偏移，位数 = $\log_2(\text{块大小})$，只用于块内寻址，与映射方式无关。

**组号**（index）用于缩小搜索范围：

- 直接映射：组号就是 cache 块号，位数 = $\log_2(\text{cache 块数})$。
- 组相联：位数 = $\log_2(\text{cache 组数})$。
- 全相联：没有该字段，位数为 0。

**标记**（tag）用于在候选块中判断是否真正命中，位数 = 物理地址位数 − 组号位数 − 偏移位数。

**访存方法**分三步：

1. 用组号找到组。
2. 组内比较 tag。
3. 用块内偏移取出数据。

![示意图](attachment://vault/e04abedf-15cd-4dc3-87f5-e301acd6fac2/kb-co-cache-address-6.svg)

> ⚠️ **tag 位数计算方法**
>
> 块内偏移和块号（index组号）位数可由 Cache 参数直接算出，tag 位数需要用物理地址位数减去其他两部分。

#### Cache 的映射方式

Cache 容量远小于主存，主存中任意块都可能被调入 Cache。**映射方式**决定一个主存块能放到 Cache 的哪些位置，本质是在命中率、访问速度、硬件复杂度之间权衡。

**直接映射**：每个主存块只能映射到 Cache 中唯一一个块。块号 $k$ 的主存块映射到第 $k \bmod M$ 个缓存块，其中 $M$ 为缓存总块数。

**全相联映射**：主存块可映射到 Cache 中任意一个块。命中率高，但访问时需并行比较所有块的标记，比较器多、硬件复杂、速度慢。

**组相联映射**：把缓存块分成若干组，主存块只能映射到某一组内的任意一个块。$N$ 路组相联表示每组有 $N$ 个缓存块，块号 $k$ 映射到第 $k \bmod (M / N)$ 组。

| 映射方式 | 比较器个数 | 需要选择器 | 硬件复杂度 | 命中率 |
|----------|-----------|-----------|-----------|--------|
| 直接映射 | 1 | 否 | 低 | 低 |
| 组相联（n 路） | n | 是 | 中 | 中 |
| 全相联 | Cache 行数 | 是 | 高 | 高 |

若是**全相联**，在这个例子里等价于 16 路组相联，每组比较 16 行，需要 16 个比较器，复杂度非常高。

### Cache 的替换算法与写策略(重要度:★★★★★)

#### Cache 的替换算法

替换算法用于全相联和组相联映射：候选块全部被占用时，需要从中选一个淘汰。

直接映射下主存块只对应唯一缓存块，冲突时直接覆盖，无需替换算法。

常用算法：

- **LRU**（最近最少使用）：淘汰最久未访问的块，命中率高。
- **FIFO**（先进先出）：淘汰最先进入的块，实现简单。
- 随机选择：实现最简，命中率不稳定。

#### Cache 的写策略

Cache 是主存的副本，写操作必须解决 Cache 与主存的数据一致性问题。写策略按命中与否分为四种。

**命中时**分两种策略：

**直写法**：每次写操作同时更新 Cache 和主存，同步完成。

**回写法**：只更新 Cache，当该块被替换时才写回主存，需要脏位配合。

**未命中时**分两种策略：

**写分配法**：先把主存块调入 Cache，再更新 Cache。

**非写分配法**：不调入 Cache，直接更新主存。

常用组合：

- **直写 + 非写分配**：两者都倾向主存操作，适合写操作不频繁的场景。
- **回写 + 写分配**：两者都倾向 Cache 操作，适合写操作频繁的场景。

### Cache 的性能与命中率(重要度:★★★★)

#### Cache 的性能与命中率

分析 Cache 性能需要四个量：

- **命中次数** $N_h$：CPU 访问 Cache 时命中的次数。
- **缺失次数** $N_m$：未命中的次数。
- **访问 Cache 耗时** $T_c$：访问一次 Cache 需要的时间。
- **缺失损失时间** $T_m$：一次缺失时，除访问 Cache 外，还要额外到主存取数据所花的时间。

无论命中还是缺失，CPU 每次访问都要**先访问 Cache**，都要花 $T_c$；只有缺失时才额外多花 $T_m$ 去主存取数据。

总访问时间 = 每次必花的 Cache 访问时间 + 缺失次数 × 缺失损失 = $N \times T_c + N_m \times T_m$。平均访问时间 = 总访问时间 ÷ 总访问次数 $N$。

$$
T_{avg} = \frac{N \times T_c + N_m \times T_m}{N}
$$

命中率越高，平均访问时间越接近 $T_c$。提高命中率的手段包括增大 Cache 容量、提高关联度、改进替换算法。
