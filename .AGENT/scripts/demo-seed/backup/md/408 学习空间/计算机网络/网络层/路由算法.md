# 路由算法

> 《计算机网络》· 网络层

### RIP(重要度:★★★★)

#### RIP 交换什么

**RIP**（路由信息协议）是一种**距离向量**协议。每个路由器只把自己的路由表（"到某网络要走几步"）周期性地发给邻居，用 **Bellman-Ford** 思路不断更新自己的表。它基于 UDP（端口 520）传输。

**RIP** 交换的就是整张路由表，本质是一张"目的网络：距离"的表。目的网络、距离、下一跳三者构成距离向量，一般认为下一跳可以省略。

每 30 秒，路由器把自己的整张路由表发给相邻的路由器，邻居收到后逐条比较，保留跳数更少的路径。

> ⚠️ **RIP 运行在哪一层、用什么封装**
>
> RIP 使用 UDP（端口 520）封装传输：RIP 报文 → UDP 数据报 → IP 数据报 → 以太网帧。RIP 要借助 UDP 和 IP 两级封装才能上链路，这和 OSPF（直接跑在 IP 上，协议号 89）、BGP（用 TCP，端口 179）都不相同。

![示意图](attachment://vault/11d95b0f-b643-48ec-a7d5-29c5dd50d738/kb-rip-basics-3.svg)

#### RIP 的缺点与举例

1. **最大跳数只有 15**：16 跳视为不可达，只适合小型网络。
2. **收敛慢**：好消息传播快、坏消息传播慢，网络出现故障时可能长时间无法收敛，甚至发生**计数到无穷**。

**计数到无穷**：假设 R1 到网络 N 原来经过 R2（2 跳），R2 到 N 经过 R3（1 跳）。某天 R2 到 R3 的链路断了，R2 发现到 N 不可达，但它仍从 R1 的定期更新里看到"R1 声称到 N 是 2 跳"，于是 R2 以为能经 R1 到 N，把自己的距离改成 3 跳并通告出去。

R1 一看 R2 说 3 跳，又更新成 4 跳……双方互相把距离一点点加下去，直到超过 16 才算不可达。这个过程浪费很长时间，期间的路径根本不通。

> ⚠️ **RIP 适用场景**
>
> 好消息传播快，坏消息传播慢。网络故障后可能长时间无法收敛，因此 RIP 只用于规模小、拓扑稳定的网络。

### OSPF(重要度:★★★★)

#### OSPF 的原理

**OSPF**（开放最短路径优先）是一种**链路状态**协议。每个路由器把自己的邻接关系和链路代价向区域内泛洪，使所有路由器获得一致的链路状态数据库，再以自己为源运行 **Dijkstra** 算法算出最短路径树。OSPF 比 RIP 收敛更快。

> 💡 **OSPF 的层数**
>
> OSPF 直接运行在 IP 之上（协议号为 89），不使用 UDP/TCP。

![示意图](attachment://vault/11d95b0f-b643-48ec-a7d5-29c5dd50d738/kb-ospf-basics-3.svg)

#### OSPF 的报文类型

OSPF 有五种基本报文类型，分工明确：
1. **Hello 报文**：发现和维护邻居关系，周期性发送。
2. **数据库描述报文**（DD）：描述自己链路状态数据库的摘要，用于邻居间同步初始状态。
3. **链路状态请求报文**（LSR）：发现自己缺少某条链路状态时，向邻居请求完整内容。
4. **链路状态更新报文**（LSU）：真正传送链路状态信息（泛洪的就是它）。
5. **链路状态确认报文**（LSAck）：确认收到链路状态更新，保证可靠。

> 💡 **OSPF 特点**
>
> 支持开销度量、支持多条等代价路径负载均衡，收敛快，适合中大型网络。

#### OSPF 如何控制洪泛规模

OSPF 用**区域划分**限制洪泛范围：每台路由器只在自己所在区域内泛洪链路状态。**区域边界路由器**只把**汇总后的路由信息**传给骨干区域和其他区域，不扩散区域内每一条链路状态。这样洪泛被限制在局部，全网不需要同步所有细节。

在**广播型链路**（如多台路由器接在同一个以太网上）里，OSPF 再通过指定路由器（DR）和备用指定路由器（BDR）进一步压缩洪泛：所有路由器只和 DR/BDR 建立邻接关系，由 DR 代表该链路泛洪，不需要每两台路由器两两建立邻接。

这样能大幅减少需要发送和处理的链路状态报文数量。

### BGP(重要度:★★★★)

#### 自治系统与 BGP

互联网被划分为许多**自治系统**（AS），每个 AS 由同一机构管理、使用统一路由策略。

AS 内部用的路由协议称为**内部网关协议**（IGP），如 RIP、OSPF。

AS 之间用的协议就是 **BGP**（边界网关协议）。

RIP、OSPF 的目的是找最短路径。

BGP 的目的是在 AS 之间根据**策略**选择可达的路径，比如绕开某些网络、优先走经济上更便宜的链路，而不一定追求最短。

> ⚠️ **BGP 基于 TCP 传输**
>
> BGP 使用 TCP（端口 179）建立会话并传输报文，因此 BGP 的可靠性由 TCP 保证，不需要自己处理确认与重传。

![示意图](attachment://vault/11d95b0f-b643-48ec-a7d5-29c5dd50d738/kb-bgp-as-3.svg)

#### AS 间和 AS 内的区别

**eBGP**（外部 BGP）运行在**不同 AS** 的路由器之间，通常是两个 AS 的边界路由器直接相连，用来通告跨 AS 的可达路由。

**iBGP**（内部 BGP）运行在**同一个 AS 内部**，让 AS 内部的路由器共享从 eBGP 学到的外部路由。

**eBGP** 管跨 AS 的外部可达性，在相邻两个 AS 的边界路由器之间建立会话，通告时会携带完整的 AS 路径。

**iBGP** 管 AS 内部共享外部路由，在同一个 AS 内的路由器之间建立会话，保证所有路由器都知道去外面的网络走哪个边界路由器。

> 💡 **AS 内部还有 IGP**
>
> iBGP 只负责分发"从外部学到的路由"，AS 内部路由器之间怎么走最短路径，仍由 IGP（RIP/OSPF）负责。两者分工不同、配合使用。

#### BGP 如何选路

BGP 交换的是路由信息加完整的 AS 路径。每条路由都附着一串 AS 序列（如 AS1-AS2-AS4-AS5），这就是它的"路径向量"。收到通告时，如果 AS 路径里出现自己的 AS 号，说明形成了环路，直接丢弃该路由。

BGP 的选路依据是**策略**，不是跳数最短。BGP 路由器综合多个属性决策，常见考量包括：

1. 本地偏好值越高越优先。
2. AS 路径越短越优先（只是参考之一）。
3. 更倾向于把流量交给客户，而不是过度转给上级 ISP。

每条 AS 根据自己的商业关系和运营策略做选择。

#### 热土豆路由策略

**热土豆**（Hot Potato）是 BGP 选路的一种常见策略。当一个 AS 从多个边界路由器收到同一条目的网络的多条 BGP 路由时，它比较从本路由器到各出口边界路由器的**IGP 内部路由代价**，选代价最小、最近的出口转发。

名字的由来：手里拿着烫手的土豆，越快扔出去越好。热土豆策略的目标是把流量尽快送出本 AS，尽量少在自己的网络里绕路，减少本 AS 内部的传输开销和时延。

**举例**：AS1 要发往网络 N，有两条 BGP 路由：一条经出口 A（AS 路径短），一条经出口 B（AS 路径长）。A 在本 AS 内部的 IGP 代价是 50，B 只有 5。

按热土豆策略，AS1 会选 B：虽然 B 的 AS 路径更长，但从本路由器走到 B 的内部代价小得多，流量能更快甩出本 AS。

> ⚠️ **热土豆 vs 最短 AS 路径**
>
> 热土豆不看 AS 路径长短，只看"到出口的 IGP 代价"。可能 AS 路径更长，但只要出口离得近就选它，它优先考虑的是降低本 AS 内部成本，而不是全局路径最短。
