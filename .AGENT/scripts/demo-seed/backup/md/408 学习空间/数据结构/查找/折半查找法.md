# 折半查找法

> 《数据结构》· 查找

### 折半查找(重要度:★★★★★)

#### 折半查找的过程与前提

**折半查找**（二分查找）每次把查找区间对半缩小：先取中间元素跟给定值比较，相等则查找成功；给定值较大则到右半区间、较小则到左半区间继续。重复直到区间为空（查找失败）。

折半查找有两个必不可少的前提：

1. 查找表**按关键字有序**。
2. 查找表**采用顺序存储**，能在 $O(1)$ 内访问任意中间元素。

**代码思路**：

```
// 在有序顺序表 a[low..high] 中查找 key
low = 1; high = n;
while (low <= high) {
  mid = (low + high) / 2;
  if (a[mid] == key) return mid;          // 查找成功
  else if (a[mid] < key) low = mid + 1;   // 到右半区间
  else high = mid - 1;                    // 到左半区间
}
return 0;                                 // 查找失败
```

复杂度为 **$O(\log_2 n)$**。每比较一次把区间缩小一半，比较次数不超过树高，时间复杂度对数级，远优于顺序查找的线性级。

**不适合直接用折半查找的结构**：

1. 有序链表：无法随机访问中间元素，不能用。
2. 无序数组：不满足有序前提，不能用。
3. 有序静态链表：用连续数组存放但逻辑靠 next 链接，无法直接定位中间下标对应的逻辑中间元素，不能用。

静态存储 ≠ 随机存取。

#### 折半判定树

**折半查找判定树**是把一次折半查找中所有可能的比较路径画成一棵二叉树：树中每个结点对应顺序表中的一个元素。用**中间位置元素作根**，左半区间元素构成左子树、右半区间元素构成右子树，递归构造得到一棵二叉树。

判定树里，比较次数按**层数**计（根是第 1 层），不是按路径长度计。查找成功时，比较次数等于目标结点所在的层数；查找失败时，等于失败结点（空指针处补的外部结点）所在层数减 1。

![示意图](attachment://vault/0b33e4ed-f7b5-4a98-852d-e1b5d3e8a4fd/kb-ds-7-3-7.svg)

上图为对关键字 1、3、5、7、9、11、13（7 个元素）构造的折半查找判定树。根为中间元素 7，左子树含 1、3、5，右子树含 9、11、13，左右子树高度均不超过 1，是二叉排序树也是平衡二叉树。

查找成功时最多比较 3 次（最底层 1、5、9、13 各需 3 次），查找失败时也最多比较 3 次（比较到最底层元素的空孩子后落空）。

![示意图](attachment://vault/0b33e4ed-f7b5-4a98-852d-e1b5d3e8a4fd/kb-ds-7-3-16.svg)

判定树普遍**偏右**。原因在于 mid = (low + high) / 2 采用**向下取整**：

1. 区间长度为偶数时，取到的 mid 是偏左那个中间位置，左子区间比右子区间少一个元素。
2. 区间长度为奇数时，左右子区间元素一样多，这一层才平衡。

上面 10 个元素 0 到 9，根取 mid = 4，左边 0、1、2、3 共 4 个，右边 5、6、7、8、9 共 5 个，根这一层就右偏。再看左子树 0 到 3（4 个元素），mid 又取 1，左边只剩 0 一个、右边 2、3 两个，继续右偏；右子树 5 到 9（5 个元素）取 mid = 7 才左右平衡。所以整体向右倾。
