### 2. 源程序（源代码文档）

- 格式：**PDF**（文本型，可搜索），每页不少于 50 行（最后一页可不足），带页码。
- 页眉（每页都有）：软件名称 + 版本号，如 `Knowbase 知识管理软件 V2.10.1`。
- 页数：本项目代码量远超 60 页，提交 **前 30 页 + 后 30 页**（共 60 页）。
- **本项目抽取规则**：
  - 只取 `src/` 与 `electron/` 下的 `.ts` / `.tsx` 源文件；
  - **排除** `node_modules/`、`out/`、`dist-electron/`、`data/`、`plugins/`、`resources/` 等非源码目录；
  - 可排除 `.css`、`.md`、配置文件（`*.config.*`、`tsconfig*.json`）等非核心代码（保留也可，看排版美观）；
  - 文件排序后拼接为一份连续文本，按每页 50 行分页；
  - 取第 1~30 页（程序开头）与最后 30 页（程序结尾）——必须是**连续代码**，不能跳选。
- **不要**在中间省略处写任何「以下省略」之类的说明文字（部分审查员视为格式问题）。

### 3. 软件说明书（15 页左右，图文结合）

结构模板：

1. 封面：软件名称、版本号、著作权人姓名
2. 目录
3. 软件概述：定位（Windows 本地知识管理工具）、核心特性（纯本地、无云端、无需注册）
4. 运行环境：Windows 10/11 64 位、内存 8GB 等
5. 安装与启动：安装包安装过程 2~3 张截图
6. 功能模块说明（核心章节，逐模块 1~3 张截图 + 功能描述）：
   - 博客（每日一篇 + 周月总结 + 自定义模板）
   - 任务（日历 / 四象限 / 子任务 / 周期任务）
   - 知识库（空间→笔记本→章节→页面四级 + 双链 + 关联网络 + 沉浸阅读）
   - 说说（碎片记录）
   - AI 助手（全局侧栏、模型配置、MCP 与技能）
   - 插件（市场、安装、主题包）
   - 工具箱（体重 / 密码本 / 强密码 / 网址导航 / 数据导出 / 番茄钟 / 习惯打卡 / 远程监督）
   - 回收站
   - 设置（外观、快捷键、数据管理）
7. 操作流程示例：如「新建知识页 → 写笔记 → 双链关联 → 查看关联网络」
8. 页眉同样标注软件名称 + 版本号

## 二、提交与流程时间线

```
① 注册实名认证       1~3 天
② 在线填报+上传材料  1 天
③ 受理（缴费单）     提交后 1~2 周（登记费 0 元）
④ 形式审查           受理日起约 30~60 个工作日（积压时 3~4 个月常见）
⑤ 补正（如有）       60 日补正期，补正后重新排队
⑥ 登记公告 + 发证    电子证书可下载，纸质证书邮寄
```

**顺利约 1~2 个月，官方时限为受理后 30 个工作日。**

## 三、补正常见原因（避坑清单）

- [ ] 源代码文档格式不符（非 PDF / 每页不足 50 行 / 无页码）
- [ ] 源代码文档页眉缺少软件名称或版本号
- [ ] 三处版本号不一致（申请表 / 源代码页眉 / 说明书页眉）
- [ ] 名称不规范或与已登记软件重名
- [ ] 开发完成日期晚于发表日期，或日期逻辑矛盾
- [ ] 说明书过于简陋（页数太少、截图模糊、与功能不符）
- [ ] 身份证扫描件不清晰
- [ ] 申请表分类选错或源程序量明显失真

## 四、拿证后

- 电子证书 + 纸质证书同时发放，证书上有登记号。
- **版本升级**：后续大版本（如 V3.0）可重新申请新登记，或对旧登记做变更；小版本不必管。
- **开源与维权**：开源不影响软著效力；你的 git 提交历史本身就是「创作完成时间」的有力证据，保留好仓库完整历史（不要 force push 清空）。
- **商用注意**：软著登记证书在应用商店上架（如企业签、软著资质审核）、政府项目投标中常作为资质证明使用。
