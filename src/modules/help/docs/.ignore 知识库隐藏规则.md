在仓库根目录创建一个名为 `.ignore` 的文件，即可用熟悉的 gitignore 语法控制哪些文件/目录**不在知识库中显示**。

## 基本用法

在仓库根（与 `.knowbase` 同级）新建 `.ignore`，每行一条规则：

```
# 注释：以 # 开头
私人草稿/
临时素材*.md
日记
build/
```

保存后知识库列表、搜索、图谱、AI 检索会自动排除命中内容（编辑器中仍然可见可编辑）。

## 语法速查（与 gitignore 一致）

| 写法 | 含义 |
| --- | --- |
| `笔记.md` | 忽略仓库内任意位置的 `笔记.md` |
| `私人/` | 忽略整个目录（含其中所有文件） |
| `*.log` | 通配符，忽略所有 `.log` 文件 |
| `doc/**/*.md` | `**` 匹配任意层级目录 |
| `/readme.md` | 以 `/` 开头 = 只匹配仓库根下的该文件 |
| `!保留.md` | `!` 取反，取消忽略（放在对应规则之后） |

## 生效范围

- **知识库**：列表、搜索、星标外的浏览、双链图谱、反链全部隐藏
- **AI 工具检索**：被忽略文件不会进入 AI 的知识上下文
- **编辑器**：完全不受影响，仍可查看与编辑（它才是文件的主人）
- **quiz**：已关联的题目记录保留，仅来源信息显示为空

## 与「草稿」的区别

- **草稿**（frontmatter `status: draft`）：知识库列表隐藏，但图谱中仍以虚化节点保留
- **.ignore**：彻底出局，图谱中也不存在，适合不想出现在任何知识场景的私密内容

## 注意事项

- 只支持仓库根一个 `.ignore`，子目录中的同名文件不生效
- 系统目录（`.knowbase`、`.attachments` 等）不受 `.ignore` 影响
- 规则写错不会报错中断，无效行会被跳过；知识库完全不见内容时优先检查规则是否写得太宽
- 修改 `.ignore` 并保存后立即生效；用外部编辑器修改则切换模块后生效
