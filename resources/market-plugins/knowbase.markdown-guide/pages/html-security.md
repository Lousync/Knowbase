# 安全注意事项与渲染器差异

## 为什么 Markdown 应用会限制 HTML

HTML 标签可能携带**脚本与活动内容**（`<script>`、`onclick`、`onload`、`<iframe>` 等），一旦被直接渲染执行，会带来注入风险。因此许多 Markdown 应用出于安全原因**只支持 HTML 标签的子集**，甚至完全不渲染原始 HTML。

## 在 Knowbase 中的行为（重点）

**Knowbase 的 Markdown 渲染器默认不渲染原始 HTML**，按防 XSS 策略对内容做净化：

| 写法 | 渲染结果 |
| --- | --- |
| `<span style="color:red">文字</span>` | 显示为纯文本（标签不生效） |
| `<table>` 表格 | 不生效——请用 GFM 表格语法 |
| `<img>` / `<a>` 标签 | 不生效——请用 Markdown 图片/链接语法 |
| 代码块内的 HTML | 正常显示为代码，安全 |

因此，在本应用中：

- **内嵌 HTML 的教学内容可直接阅读**（以代码块呈现）
- **需要实际效果时**，改用应用支持的语法：表格用 `|` 语法、图片用 `![]()`、强调用 `**` / `*`、链接用 `[]()`
- 数学公式用 `$...$` / `$$...$$`，折叠内容用 ```spoiler 块（本应用扩展）

## 通用安全清单

1. 只信任你了解的来源的 HTML 内容
2. 粘贴来自网页的富文本前，先清理脚本
3. 需要实际渲染 HTML 时，选择明确声明支持的应用，并确认其净化策略
4. 文档化内容优先用 Markdown 语法保持可移植性
