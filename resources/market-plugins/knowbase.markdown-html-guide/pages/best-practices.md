# HTML 用法最佳实践

## 官方建议清单

1. **查看应用手册**：出于安全原因，并非所有 Markdown 应用都支持内嵌 HTML——如有疑问先查对应应用文档；有些应用只支持 HTML 标签的子集
2. **区块标签前后使用空行**：`<div>`、`<table>`、`<pre>`、`<p>` 等块级元素与其它内容之间要留空行
3. **不要用制表符/空格缩进**：对 HTML 标签缩进可能影响格式
4. **块级标签内不使用 Markdown**：如 `<p>italic and **bold**</p>` 不会生效，请用 HTML 自身语法

## 排版对照

```markdown
<!-- ✅ 正确：空行分隔、无缩进 -->
这是一段文字。

<div>
    块级内容
</div>

另一段文字。

<!-- ❌ 错误：紧贴段落、有缩进 -->
<div>
    内容
</div>
```

## 何时选 HTML、何时选 Markdown

| 需求 | 选择 |
| --- | --- |
| 快速写作、纯文本排版 | Markdown（更简洁） |
| 控制颜色、宽度、对齐等属性 | 内联 HTML |
| 复杂表格、布局容器 | 区块 HTML |
| 跨应用分享文档 | 尽量只用 Markdown（HTML 兼容性差） |

## 与 Markdown 扩展语法的取舍

很多扩展语法（如 GFM 表格、任务列表）能覆盖大部分常见需求，且跨应用兼容性更好。**能不用 HTML 就不用**——这是保持文档可移植性的基本原则。
