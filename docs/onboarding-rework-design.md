# 新用户引导优化方案（onboarding-rework）

- 日期：2026-09-08
- 状态：**方案讨论稿，待拍板后实施**
- 关联：`docs/rework-master-plan.md`、`.AGENT/docs/读写分工设计.md`
- 类型：UI/UX 改进（表现层为主，不动数据层与业务逻辑）

---

## 1. 背景与问题定义

用户反馈：**软件缺少人性化指导，新用户接触软件"两眼一抹黑"**。

需要澄清的事实：软件并非没有引导。首启 6 步向导、仓库选择页、19 篇帮助文档都已存在。问题出在引导的**形态**——它是"一次性展示型"，看完之后用户没有任何一条"跟着做"的路径，核心概念零解释，空状态全是死胡同。

### 目标

新用户在 **10 分钟内**完成"写第一页笔记并在知识库看到它"的最小闭环；24 小时内知道去哪找答案、怎么备份。

## 3. 问题诊断：四个断层

| # | 断层 | 表现 | 后果 |
|---|---|---|---|
| D1 | **看完 ≠ 学会** | 6 步一次塞 7 模块 + 5 组快捷键，是产品说明书不是上手路径 | 点完"开始使用"后"第一篇笔记在哪写"没有得到回答 |
| D2 | **空状态是死胡同** | 编辑器空白 Monaco、知识库"暂无内容"，只有句号没有逗号 | 新用户卡住高发点恰恰是这些空白页 |
| D3 | **核心心智模型零解释** | 读写分工（编辑器=唯一写入方，知识库=阅读器；无 frontmatter id 的文件=草稿，知识库不显示）引导里只字未提 | 新用户 100% 在知识库找"新建按钮"找不到；写了文件知识库看不见，双重挫败 |
| D4 | **帮助无路径、入口深** | 19 篇按字母序排，无阅读顺序；重看引导埋最深；Ctrl+Shift+P / Ctrl+O 等 VS Code 式能力对新手不可见 | 引导结束后无任何"继续学习"钩子 |

---

## 4. 设计原则

1. **行动优先**：每处引导必须给出"现在可以做什么"的可点击动作，而非仅文字说明。
2. **不重复造轮子**：复用现有 `onSwitchTab` / `onboarding:show` / 自定义事件通道；只新增 1 个 settings 键、1 篇帮助文档。
3. **可找回**：所有一次性引导都必须有再次进入的路径（命令面板 / 设置 / 帮助置顶）。
4. **不打扰**：P2 类 coach-mark、弹窗式提示明确不做；提示类元素均一次性且可关。

## 6. P0 详细设计

### P0-1 向导终章行动化

**目标**：把"看完了"变成"跟着做"。

**形式（待拍板，二选一）**：
- **方案 A（推荐）**：新增第 7 步"三件事"行动页。三张大卡片，每张一个主按钮：
  1. **写第一页** → `onSwitchTab('editor')` + 派发编辑器新建事件（复用 `pendingOpenRel` 同层通道或编辑器现有新建入口），并结束向导；
  2. **读《快速上手》** → 切到帮助模块并定位该文档，结束向导；
  3. **装一个知识包** → 切到插件模块，结束向导。
  - 三卡片下方保留"先随便看看"按钮 = 原"开始使用"直接完成。
- **方案 B**：不改步数，把现有第 5 步（快捷键）压缩，与"三件事"合并为终页。改动更小但页面拥挤，与"厌恶冗余元素"的 UI 偏好有冲突风险。

**实现要点**：
- `total` 由 6 → 7，键盘导航（←/→/Enter）自动适配，无需额外处理；
- "跳过引导"按钮在终章语义不变（=直接完成）；
- 向导内执行动作卡片点击 = **完成引导 + 跳转**，避免 overlay 叠加在目标模块上（Onboarding 是 `fixed inset-0` 全屏层，必须先关再跳）。

### P0-2 空状态行动化

**目标**：三大死胡同每个都有"下一步"。

#### ① 编辑器空态（最高优先）

- 触发条件：`MonacoPane` 的 `doc === null` 且当前已有仓库（无仓库走 WelcomeOverlay，不冲突）。
- 内容：
  - 标题"从一张白纸开始"；
  - 主按钮"新建第一篇笔记"（复用编辑器现有新建文件逻辑 `createFile`）；
  - 副按钮"打开快速上手"（切帮助模块）；
  - 三行入门提示：左侧文件树"+"可新建文件 / 文件夹 / 知识页；`Ctrl+N` 快速新建；内容自动保存。
- 注意：编辑器在 workbench 布局下 `sidebarHosted`，空态只占据编辑区中栏，不动文件树。

#### ② 知识库空库态

- 触发条件：知识库索引为空（无页面）且无 frontmatter 提示场景。
- 内容：读写分工一句话说明（"知识库是阅读器：在编辑器写入的内容会出现在这里"）+ 主按钮"去编辑器写第一页"。
- 跳转通道：派发 `kb-open-in-editor` 不合适（它要求 relPath）；**新增轻量事件 `editor:open`（App 监听后 `setActiveTab('editor')`），与现有 `settings:open` / `help:open` 同构**，实现成本一行。

#### ③ 帮助首页"新用户"卡片

- `HelpModule` 列表顶部固定一张卡片："第一次使用 Knowbase？从《快速上手》开始（5 分钟）"→ 点击打开该文档。
- 该卡片常驻不消失（帮助是可找回入口，不是打扰型提示）。

### P0-3 《快速上手》文档 + 分类置顶

**新增文件**：`src/modules/help/docs/快速上手.md`（frontmatter：`title: 快速上手`、`category: 入门`、`icon: Rocket`）。

**内容大纲（任务线，非功能线）**：

```
# 快速上手
## 先认识三个区（2 分钟）
   活动栏 / 编辑器 / 知识库，一张示意图 + 一句话职责
## 第一个 10 分钟：写第一页
   选定仓库 → Ctrl+N 新建 → 写正文 → 自动保存 → 它去哪了
## 第一个小时：让知识库"认识"你的笔记
   frontmatter 与 id（为什么有的文件在知识库看不到——草稿机制）
   标签、双链 [[]]、目录组织
## 第一周：养成三个习惯
   备份（导出 ZIP / 拖入恢复）、插件知识包、快捷键 TOP5
## 常见困惑
   "我在知识库找不到新建按钮" / "写的文件知识库不显示" / "AI 怎么配置"
```

**排序权重（docsLoader.ts）**：`parseFrontmatter` 已支持任意 kv；新增可选 `weight` 字段，`loadHelpDocs` 排序改为 `weight ASC（缺省 100）→ category → title`。《快速上手》写 `weight: 0`，"入门"类自然置顶。向后兼容：存量文档无 weight 不受影响。

## 8. 明确不做（P2）

- **首次进模块的一次性 coach-mark tooltip**：实现成本高、时机判断复杂、易构成打扰。
- **空状态插画**：纯审美收益，与"厌恶冗余元素"偏好相悖。
- **多语言 / 引导视频**：当前无需求。

## 10. 实施顺序与验收

### 实施顺序（拍板后）

1. P0-3 文档 + docsLoader 权重（独立无依赖，先行）
2. P0-2 三处空态 + `editor:open` 事件
3. P0-1 向导终章（依赖 P0-3 的文档存在）
4. P1 三项
5. 统一验收（不做阶段交付）

### 验收标准

- 门禁：`tsc --noEmit -p tsconfig.node.json` 与 `tsconfig.web.json` 全绿；
- smoke（`npm run dev`，用 dev 设置模拟首启）：
  - 首启：无仓库 → WelcomeOverlay → 建仓 → 向导出现 → 终章三件事按钮各自可用且跳转正确；
  - 空态：空仓库下编辑器空态出现、按钮新建成功；知识库空态文案与跳转正确；
  - 帮助：《快速上手》置顶可读；帮助首页卡片可点开文档；
  - 找回：命令面板两条命令可用；设置→关于重看引导不变；
- 回归边界：VaultPicker 流程、模块保活机制、`onboardingDone` 写入时机均不改动。

### 风险与注意

- **帮助文档必须 LF**：`docsLoader` 曾因 CRLF 导致 frontmatter 解析全灭，新增 md 保存为 LF 并人工确认；
- `Onboarding` 的 `total` 改动注意键盘循环与进度圆点渲染（同源变量，风险低）；
- 空态改动全部在模块内部，不触碰 App 层保活 keyed 数组结构；
- 新增 settings 键走现有 `update()` 通道，不涉及迁移。
