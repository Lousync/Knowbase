# AI 沉浸式 Agent 模式设计（场景全景 + 信息架构）

> 状态：方案讨论稿（2026-09-03）。归属：AI 助手域深化的下阶段；与本仓库 `feature/agent-file-tools` 已完成的
> 「vault 工具链（B0–B3）+ web.read + docs.read-text + 面板过程可视化」直接衔接。
> 配套：界面原型图（会话内可视化）见本节 §6；轻问答界面（侧栏 AssistantPanel）维持现状不动。

## 1. 动机与定位

现有 AI 问答是**小侧栏**：快问快答顺手（用户认可，不改）。但它撑不起**重任务**：
教学对话要"喂资料 → 分章精讲 → 出题 → 生成复习计划"，过程中要随时查看资料来源、
AI 拟写的成果、步骤进度——小侧栏放不下，体验局促。

**沉浸式 Agent 模式** = 一个**全尺寸工作台**（独立 Tab，占用主内容区），
围绕"**目标 + 过程 + 素材 + 产物**"四个对象组织界面，让用户能坐着看 agent 干完一件
复杂事：读 3 份 PDF/5 个网址 → 拟一份学习方案 → 分章开讲 → 出题测验 → 把方案与笔记
落进知识库织网。轻问答回答"是什么"，沉浸模式完成"学到会、整理好"。

### 定位对照

| | 轻问答（现状侧栏） | 沉浸式 Agent（本设计） |
|---|---|---|
| 界面 | 窄侧栏悬浮 | 全尺寸 Tab（可全屏/分栏） |
| 任务 | 单轮/少轮问答 | 多阶段目标（教学/研读/写作/整理） |
| 素材 | 上下文一页 | 资料来源集合（URL/PDF/PPT/笔记）可管理 |
| 过程 | 气泡步骤（已做） | 步骤时间线 + 阶段进度 + 可暂停/续讲 |
| 产物 | 聊完即走 | 产物区：草稿/方案/复习卡，预览 → 一键写入知识库 |
| 入口 | Ctrl+J | 独立入口（命令面板/侧栏图标/Tab） |

## 2. 目标场景全景（用户故事）

### S1 · 私人导师教学（第一场景）
用户丢给 agent 一份或几份资料（**网址 / PDF / PPT / 已有笔记**），要求"教我学会"：
1. **吃资料**：agent 通读（`docs.read-text` / `web.read` / `vault.read`），在"资料来源"栏逐条标记 已读/提取页数
2. **摸底定计划**：问一句基础（可选）→ 产出**学习方案草稿**（章节顺序、每日计划、关联资料标注）
3. **分章精讲**：按方案逐章：讲概念 → 关联本地笔记 → 用户可随时打断问细节
4. **检验**：agent 出题（选择/填空/简答）→ 用户作答 → agent 批改讲解错因
5. **沉淀**：生成 **复习卡/知识页**（含双链到资料与相关笔记），一键写入知识库
贯穿全过程的对话与产物都**落在当前会话**，切走回来仍在（AgentRunner 会话已落库，产物区新扩）。

### S2 · 深度研读与知识织网
用户说"把仓库里讲『虚拟内存』的都找出来，读一遍给我讲清楚，并整理成一张专题页，链上所有来源"。
agent：`vault.search` 定位 → 批量 `vault.read` → 综合讲解 → 产出专题 .md 草稿 →
预览 → 写入 → 图谱长出新连线。

### S3 · 长文与结构化写作
"帮我写一篇 3000 字的《Rust 内存安全》科普，大纲先给我确认，引用资料我放在来源里"。
写作场景需要**草稿-确认-分节续写**节奏：主画布容纳长文预览，右栏是引用来源，
agent 按节写，用户逐节确认/修改意见回传。

### S4 · 知识库整理与保洁（人审模式）
"扫描仓库，找出孤儿页、标题相近重复的、没打标签的，给我一份整理建议清单，
我确认后再动手"。agent 输出**建议清单（不自动改）**，用户勾选后执行
（`vault.rename/trash/edit` 已在护栏内）——沉浸模式把"清单 + 勾选 + 执行结果"三态
放同一个界面。

### S5 · 周期复盘报告
"总结我这一周"：agent 读日程/打卡/日记/番茄钟 → 生成周报草稿（成就/回落/下周建议）→
预览 → 写入"每周总结"笔记。结构化数据走既有模块工具，输出走 vault 写入。

### S6 · 错题/刷题陪练（衔接错题本）
给定章节 → agent 从错题本/知识包抽题陪练 → 逐题讲解 → 新错题自动建议入库。
（依赖 quiz 侧通道，列为远期扩展，不阻塞 v1。）

## 3. 沉浸模式的信息架构（界面五区）

```
┌────────────────────────────────────────────────────────────────────┐
│ A 顶栏：模式标识 · 当前目标（可编辑）· 阶段标签 · 来源管理 · 保存   │
├──────────┬─────────────────────────────────────────────┬───────────┤
│ B 左列    │ C 主画布（对话 / 长文 / 列表切换）           │ D 右栏     │
│ 任务步骤  │   步骤时间线：                              │ 资料来源   │
│ ① 通读 ✓ │   [卡片] 正在调用 vault.read「笔记/x.md」    │ 📄 OS.pdf  │
│ ② 大纲 ✓ │   [卡片] 精讲·第 2 章（可折叠/可回看）       │   ✓已读    │
│ ③ 精讲 ● │   输入提示：讲什么 / 出题 / 生成复习卡       │ 🌐 网址…   │
│ ④ 测验 ○ │                                           │ 📝 笔记×3  │
│ ⑤ 沉淀 ○ │                                           │ ────────   │
│          │                                           │ 产物区     │
│          │                                           │ 两周计划草稿│
│          │                                           │ [预览][写入]│
├──────────┴─────────────────────────────────────────────┴───────────┤
│ E 底栏：素材 n · 进度 3/5 · 本次改动 n（可点跳编辑器）· 停止/继续     │
└────────────────────────────────────────────────────────────────────┘
```

- **A 顶栏**：当前目标一句话（"操作系统：跟我学两周"），可随时编辑让 agent 对齐；
  来源管理按钮（拖入文件/粘贴网址/选仓库笔记）。
- **B 左列 · 任务步骤**：把大目标拆成可见阶段（agent 自拟、用户可增删/调整顺序/单独跳过），
  每步有 ✓/●/○ 状态——**教学到哪一步一眼可见**，可点击跳回该步的产出。
- **C 主画布**：核心输出区。三种视图按需切换：`时间线`（默认，步骤卡片流，大字号舒适阅读）、
  `文档`（长文/方案整篇预览，供 S3 写作审阅）、`对比`（新旧版本 diff，供产物确认）。
- **D 右栏**：① 资料来源：会话级素材清单（状态：待读/已读/页数/失败原因），可增删；
  ② 产物区：agent 拟好的笔记/方案/复习卡草稿（多份可切），每份带 `[预览] [写入知识库]`，
  写入走受控通道并通知编辑器（点击可跳转，P 批能力直接复用）。
- **E 底栏**：素材数/步骤进度/本次改动数与清单（复用改动卡）+ 停止/继续。

## 4. 与现有架构的衔接（哪些直接复用）

| 能力 | 现状 | 沉浸模式用途 |
|---|---|---|
| AgentRunner + ToolRegistry | ✅ 循环/权限/审计 | 完全复用，不改协议 |
| vault.* 工具族（读写搜改/回收站） | ✅ B0–B3 | 主画布产物写入、S4 整理执行 |
| docs.read-text / web.read | ✅ | S1 吃资料（PDF/PPT/网址） |
| knowledge 结构化工具 / 模块工具 | ✅ | S5 复盘取数、S1 关联本地知识 |
| 会话落库 + 会话列表 | ✅ | 沉浸会话也是 AgentRunner 会话（同一库），可续 |
| 过程实时推送 agent:step | ✅ P 批 | 步骤时间线喂数据源 |
| 改动清单 + 点击跳编辑器 | ✅ P 批 | 底栏改动卡复用 |
| 编辑器唯一写方 + 外部变更弹窗 | ✅ | AI 写入的文档产物，用户在编辑器打开即见一致 |

**需要新增（v1 最小）**：
1. **沉浸前端模块**（新 Tab）：五区布局 + 步骤/素材/产物 state 模型（会话级持久化于内存与
   会话库 meta）
2. **素材管理通道**：拖入本地 PDF/PPT → 复制进仓库（或授权读取）→ 记入会话素材集；
   URL 直接入素材集（走 web.read）
3. **阶段与产物元数据**：AgentChatRequest 的 context 升级为可携带 `sources[] / plan[]`；
   或 v1 简单化——阶段由 system 提示词约定，UI 仅展示 agent:step + 约定动作消息
4. **产物预览/写入按钮**：把"回复中的代码块/草稿"落库——v1 简单化：agent 按约定产出
   `【产物:标题】…` 块，UI 提取显示在产物区并带"写入"（调 vault.write，走既有权限）

> 设计原则：**协议不动，层变**。复用现成工具/事件/权限体系，沉浸模式只是换一层更宽的
> UI + 更结构化的任务组织，不在 agent 内核上开新洞。

## 5. 交互节奏差异（与轻问答的关键不同）

轻问答=一次性请求；沉浸教学/写作需要**节奏控制**：
- **阶段推进制**：agent 拟完大纲不直接开讲，停在"大纲待确认"；用户点"继续"才进精讲。
  失控风险与信息过载同时降低（≤8 轮限制按阶段分段消化：每阶段一轮 AgentRunner 循环）。
- **打断与回看**：用户随时提小问题 → 该问题作为对话行插入，agent 回答后回到原阶段；
  步骤卡片可折叠（详情收入卡片，主画布保持呼吸感）。
- **长输出分节落库**：写长文/S4 建议清单时，产物先落"产物区草稿"，用户审阅后再写库——
  避免"AI 一口气改完你才发现"。

## 7. 待拍板点（逐个击破）

| # | 问题 | 结论（2026-09-03 拍板） |
|---|---|---|
| Q1 | 形态 | **独立全屏 Tab**（主内容区页面，复用现有 Tab/Workbench 体系；轻问答侧栏保留） |
| Q2 | v1 聚焦 | **通用工作台**（五区布局一次做全；S1–S5 为场景模板，界面不随场景改形） |
| Q3 | 阶段节奏 | A 阶段确认制（推荐，大纲待确认再开讲）/ B 全自动跑完可中断 |
| Q4 | 素材入口 | A 拖入文件自动复制进仓库 + 贴 URL + 选仓库笔记 / B v1 只贴 URL 与选仓库内文件 |
| Q5 | 产物写入 | A 产物区草稿 → 人工点「写入知识库」/ B 自动写入 + 底栏改动清单可撤销 |
| Q6 | 长文输出 | 分节落草稿（推荐）vs 整篇一次出 |
| Q7 | 与错题本/quiz 联动（S6） | 本期不做，排远期 |

## 8. 分期建议（拍板后细化）
