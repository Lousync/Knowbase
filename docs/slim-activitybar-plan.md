# 活动栏精简方案：默认三件套 + 引导场景选择

> 2026-09-11 · 原型已确认（`outputs/slim-activitybar-prototype.html`），本文档为落码依据。

## 1. 背景与拍板

推广视角下，「功能全」是卖点文案，「界面简」是第一印象。现状：新用户首启活动栏全量 8 模块 + 用户 + 设置 = 10 个图标，信息过载。

已拍板决策：

| 决策项 | 结论 |
|--------|------|
| 默认露出 | **编辑器 + 知识库 + AI教学** 三件套（AI教学是核心创新点，保留一级入口，不降级插件） |
| 力度 | 只做「藏」（渐进披露）；「并」（博客/说说整合、工具箱分组）与「删/降级」另议 |
| 原则 | **删入口不删能力**：隐藏模块的数据/快捷键/命令面板入口全保留，右键活动栏一处找回 |
| 载体 | 场景选择**并入现有新手引导**（6→7 步，插在「核心功能一览」之后），单页多选，**无预览页** |

## 2. 改动点（文件级）

### 2.1 `src/components/shared/Onboarding.tsx`（主要改动）

1. **步骤数 6 → 7**：`step === 2` 插入「你的使用场景」，原 2~5 步顺移为 3~6。
2. **场景步骤**：8 个一级模块卡片多选（复用 ActivityBar 的模块清单与 id），默认勾选三件套；用户点选即记 `sceneTouched`；清空时强制保留编辑器。
3. **生效时机统一收口**：完成（最后一步「开始使用」）与「跳过引导」走同一个 `finish()`：
   - `sceneTouched` → 按所选写 `activityBarHidden`（= 8 模块 id − 所选）；
   - 未触碰 → 写推荐默认三件套的补集；
   - **仅首启运行（`!onboardingDone`）或用户触碰过场景才写盘**——设置里重开引导浏览一遍不允许重置老用户的活动栏；
   - `startupTab` 不在可见集合时 `onSwitchTab` 到第一个可见模块。
4. **「核心功能一览」清单补全**：现有 7 项缺**编辑器**与**AI教学**，补为 9 项，保证选场景前用户已认识全部 8 个一级模块 + AI 助手。

### 2.2 `src/components/shared/ActivityBar.tsx`（零结构改动）

显隐机制（`activityBarHidden` + 右键菜单）与排序迁移完全复用，不改默认值——新用户的三件套由引导完成时写入，而非 ActivityBar 改 fallback（避免殃及 `activityBarHidden` 未设置的老用户）。

### 2.3 `src/App.tsx`（零改动）

启动 Tab 已有 hidden 回退链（startupTab → order → 首个可见）；引导关闭后的 Tab 纠偏由 Onboarding 的 `onSwitchTab` 完成。

## 3. 生效矩阵

| 用户 | 行为 | 结果 |
|------|------|------|
| 全新安装 | 完成引导 | 所选模块常驻（未选=默认三件套） |
| 全新安装 | 跳过引导 | 默认三件套 |
| 老用户升级 | — | 不触发引导；`activityBarHidden` 未设置 → 保持全量，**零影响** |
| 任意 | 右键活动栏 | 随时显示/隐藏找回 |

## 4. 验收清单

- [ ] `tsc --noEmit -p tsconfig.web.json` 无新增错误（存量债 ~25 不计）
- [ ] `npm run build` 通过

- [ ] 设置中重开引导、走完不点场景 → 活动栏不被重置
