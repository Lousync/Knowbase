## 1. 目标效果拆解

把 Obsidian 图谱「想要的那种感觉」拆成 8 个独立的动画/交互单元，每一个都可单独验收：

| # | 效果 | 描述 | 优先级 |
|---|------|------|--------|
| A1 | 入场动画 | 打开图谱时节点从中心散开、逐渐稳定，像一团星云展开 | P0 |
| A2 | 物理微动 | 布局未冷却时节点持续被弹簧/斥力拉扯，肉眼可见的"呼吸感" | P0 |
| A3 | Hover 高亮 | 悬停节点：邻居保持亮色，其余节点与边**平滑淡化**；连接边高亮 | P0 |
| A4 | 拖拽节点 | 拖动节点，与它相连的子图被"拖拽力"拉扯跟着移动，松手回弹 | P0 |
| A5 | 缩放/平移 | 滚轮缩放（围绕鼠标位置）、拖拽平移，带**惯性滑动** | P0 |
| A6 | 点击跳转 | 点击节点 → 切到编辑器打开该 .md；同时有聚焦动画（视口平滑移向该点） | P1 |
| A7 | 本地图谱 | 以当前页面为中心，逐层展开 1~2 度邻居的星状图，带展开动画 | P1 |
| A8 | 淡入/离场 | 节点增删（新建/删除文件）时新节点淡入、消失节点收缩，布局局部重排 | P2 |

**P0 = 没有 it 就不像 Obsidian 图谱的底线；P1 = 增强体验；P2 = 锦上添花。**

## 2. Obsidian 的实现机制分析（官方确认）

来源：Obsidian 官方论坛回复（Silver，2020）+ 社区逆向（obsidian-typings 项目对 `GraphRenderer` 的类型还原）+ 官方 Discord 员工确认。

| 组件 | Obsidian 的做法 | 对我们的启示 |
|------|----------------|-------------|
| 力导向模拟 | **d3-force**（官方确认） | 直接用 d3-force，不要自研物理 |
| 渲染 | **PixiJS（WebGL）**，早期曾用 d3 全家桶，后拆开 | 渲染层与模拟层解耦，渲染器可替换 |
| 模拟线程 | **Web Worker**：`GraphRenderer.worker` + `workerResults`，主线程只拿结果渲染 | 模拟不卡 UI；Knowbase 主窗口还有 Monaco，更要拆 |
| 缩放 | `scale` 向 `targetScale` **逐帧插值**，不是瞬时跳变 | 动画感的关键之一：一切状态变化都走缓动 |
| 平移 | `panvX/panvY` 速度变量 → 松手后**惯性滑动**衰减 | 同上 |
| 停止条件 | `idleFrames`，**连续 60 帧无变化即停渲染循环**，省电 | 冷却机制，不能永远 60fps 空转 |
| 颜色 | `colors` 从 app CSS 变量实时读取（`testCSS()` 重读） | 主题切换免通知，直接读 CSS 变量 |
| 交互 | onNodeHover / onNodeClick / onNodeRightClick / 拖拽 / 滚轮，独立事件层 | 事件与渲染分离 |

d3-force 的四种力（Obsidian 图谱的物理本质，也是我们参数面板的来源）：

```
link 力      （弹簧）：相邻节点拉向目标距离，F = k·(d − L)
many-body 力 （斥力）：所有节点两两互斥（Barnes-Hut 四叉树优化为 O(n log n)）
center 力    （向心）：整体向画布中心聚拢，防止散飞
collision 力 （碰撞）：防止节点重叠，维持最小半径间距

alpha 系数：从 1 开始逐帧衰减到 alphaMin(~0.001)，衰减过程中力的作用减弱
           → 这就是「入场散开 → 逐渐稳定 → 停止」的动画本质
```

## 3. Knowbase 数据源设计（GraphIndex）

图谱的数据不是现成的，需要在 knowledgeIndex 之上长出**链接索引**：

### 3.1 节点与边

- **节点** = 仓库内所有 .md 页面（来自 knowledgeIndex，已含 id/title/path/tags/category/updated）
- **边** = `[[双链]]` 解析结果。解析规则与知识库模块现有双链一致：`[[文件名|显示名]]`、`[[文件名#标题]]`
  - 解析目标按 **页面标题 → 文件名** 两级匹配（复用 knowledgeIndex 的 findKnowledgePage）
  - **未解析链接**：渲染为虚线灰色节点（Obsidian 同款），不算实边，可过滤
- **标签节点**（可开关，**默认开启**，2026-09-02 拍板）：frontmatter tags 也作为节点入图，边 = 页面→标签；Obsidian 默认关闭，我们反其道行之——319 个标签全量入图，同时提供开关与按标签过滤，避免不想看时干扰
- **孤儿页**：无边节点渲染为小号灰点，可过滤（默认显示）

### 3.2 落盘与失效

```
.knowbase/cache/graph.json
{
  "schemaVersion": 1,
  "builtAt": 1788...,
  "nodes": [{ "id": "...", "title": "...", "path": "...", "degree": 3, "kind": "page|tag" }],
  "edges": [{ "s": "<id>", "t": "<id>" }],          // 去重后的无向边
  "unresolved": [{ "name": "...", "refs": ["<id>"] }] // 未解析引用聚合成虚节点
}
```

失效策略与 knowledgeIndex 完全一致：**写时失效、用时懒重建**（`ws:writeFile/createFile/rename/trash` 的 4 个失效钩子已存在，图谱索引挂在同一组钩子上，无需新增 IPC）。

### 3.3 双链统一的交汇点（关键架构决策）

链接解析只做一份，放在主进程 GraphIndex，三方消费：

```
                ┌─ 图谱视图（Canvas 渲染）
GraphIndex ─────┼─ 编辑器模块：[[..]] 自动补全 + 跳转（阶段 3 待做项）
                └─ 知识库模块：现有双链/反链改读同一份（消除两套解析）
```

这样图谱不是孤立功能，而是把「双链系统」从知识库模块下沉为**仓库级基础设施**——正好呼应重构主线。

## 4. 技术选型

| 方案 | 组成 | 优点 | 缺点 | 适用 |
|------|------|------|------|------|
| **A（推荐起步）** | **d3-force + Canvas 2D + Web Worker** | d3-force 仅 ~30KB、无依赖负担；Canvas 2D 在 2k 节点内 60fps 无压力；Worker 跑模拟，主线程零卡顿 | >5k 节点渲染吃力 | 当前规模（216 页 + 319 标签 ≈ 550 节点，数百边）**绰绰有余** |
| B（预留升级） | d3-force + PixiJS(WebGL) + Worker | Obsidian 同款，万级节点 | 引入 pixi.js ~450KB；打包体积敏感 | >3~5k 节点再上 |
| C（参考） | obsigraph（社区库，pixi+d3 封装） | 现成轮子，Obsidian 观感还原度高 | 第三方维护、可控性差、与我们主题/CSS 变量体系不合 | 只读源码借鉴参数，不引包 |

**选 A 的核心理由**：规模决定了 Canvas 2D 完全够用；且 `d3-force` 是纯计算库（无 DOM 依赖），天然适合放 Worker。渲染层做一个 `GraphRenderer` 接口抽象，未来换 PixiJS 只换渲染器不动物理层。
**（2026-09-02 拍板：选 A，接受引入 d3-force。）**

**依赖决策**：仅新增 `d3-force`（或从 d3 按需引 `d3-quadtree`/`d3-dispatch` 等 d3-force 的内部依赖，tree-shaking 后 ~30KB）。与 lanShare「不引入 npm 包」不同——力导向物理自研成本高、d3-force 是事实标准，值得破例。

## 5. 动画系统规格（本文档核心）

### 5.1 帧循环与冷却

```
rAF 帧循环（仅活跃时运行）:
  1. simulation.tick()          ← Worker 内 d3-force tick
  2. 更新插值状态（zoom→targetScale、hoverAlpha→targetAlpha 等全部 lerp）
  3. Canvas 重绘
  4. 若 |alpha| < alphaMin 且无进行中的插值 且无交互 → idleFrames++
     idleFrames ≥ 60 → 停止 rAF（Obsidian 同款）；任何事件唤醒
```

### 5.2 各动画单元的实现要点

| 单元 | 机制 | 参数初值（可调） |
|------|------|------------------|
| A1 入场 | 节点初始位置=中心附近随机抖动，alpha=1 自然衰减 | linkDistance 120 / chargeStrength −300 / collision 0.5 |
| A3 Hover 淡化 | 每个 node/edge 存 `displayAlpha`，逐帧向 `targetAlpha` lerp(0.15)；邻居=1，其余=0.08，边两端有一端是邻居才保留 | 淡化过渡 ~200ms |
| A4 拖拽 | d3 的 `fx/fy` 固定坐标跟鼠标；被拖节点的邻居受 link 力自然被拉扯；松手清 fx/fy 回弹 | 拖拽时临时提高 alpha 重启微动 |
| A5 惯性平移 | pointermove 记录速度，pointerup 后 `pan += v; v *= 0.92` 衰减至 <0.1 停 | 缩放插值系数 0.2/帧 |
| A6 点击聚焦 | targetPan/Scale 设置后逐帧插值，随后 `openFile(rootId, relPath)` 切编辑器 | — |
| A7 本地图谱 | 子图 = 当前页 + 1~2 度邻居（BFS）；展开动画 = 新节点从中心页位置出发 + alpha 0→1 | 度数默认 1 |
| A8 增删动画 | 增：r 从 0 缓动到目标半径；删：r→0 后移除；局部 alpha 重启 | — |

### 5.3 节点视觉编码（对齐 Obsidian）

- **半径** ∝ 度数（连接数）：`r = minR + k·√degree`，范围 4~14px
- **颜色**：默认统一色（读 CSS 变量 `--accent` 系）；可选**按颜色分组**（按一级目录/空间着色）
- **标签**：缩放 > 阈值才显示（Obsidian 的 `fTextShowMult` 行为），避免小缩放时文字糊成一片
- **边**：1px 半透明直线；hover 时相关边加亮；箭头默认关（Obsidian 默认也关）

## 8. 风险与边界

1. **Worker 与打包**：electron-vite 下 Worker 文件需要作为独立 chunk 构建（`new Worker(new URL(...))` 语法），dev/prod 路径都要验证；备选降级：节点 <800 时直接主线程 tick（Canvas 重绘才是大头，216 页规模主线程也够）
2. **双链口径差异**：知识库模块现有双链解析与编辑器裸 .md 的解析必须统一到 GraphIndex，否则图谱边数和知识库反链面板对不上——G0 验收专门设了对账项
3. **回收站/隐藏目录**：`.knowbase/`、`_attachments/`、回收站中的页面不进图（knowledgeIndex 已有跳过逻辑，直接复用）
4. **性能红线**：节点 >2000 时自动开启视口裁剪（只画可见区域）；>5000 提示切换简化模式（关标签/关动画）——为将来大仓库预留
5. **主题**：颜色一律运行时读 CSS 变量，不做硬编码色值（插件主题包切换免通知）
