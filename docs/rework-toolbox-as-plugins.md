# 工具箱插件化评估

> 归属：[rework-master-plan.md](./rework-master-plan.md) D3 / R7。状态：评估定稿（2026-09-02），作为 v3 插件运行时的验证用例集。
> 判定基准：`rework-plugin-openness.md`（沙箱 + capability 网关）+ `plugin-api-v2-design.md`（kb.store / kb.vault 已有设计）。

## 0. 现状核查（2026-09-02 12:30 实测修正）

- **强密码生成器已经不是工具箱工具**：`src/modules/toolbox/index.tsx` 现行 10 工具（体重/密码本/网址导航/数据导出/设备传输/番茄钟/习惯打卡/远程监督/单词本/PDF 工具箱），**生成器已被移除并转为市场插件**（pluginRegistry.ts 注释：「已不再随应用分发的内置插件,降级为普通插件(解锁卸载,如强密码生成器转市场)」）
- **当前插件系统已具备 capability 骨架**：`pluginRegistry.ts` 实测支持 `type: 'declarative' | 'ui'`（code 仍拒收）+ `capabilities`（≤10 项强制校验）+ `grantedCapabilities`（内置 UI 插件全量预授权、其余需授权）+ contributions（tables 需 data 能力 / views / tools 按能力门禁）+ legacy 容忍
- 含义：**v3（开放 JS 执行）是在已有骨架上扩展能力面，不是从零建**；`rework-plugin-openness.md` 的基线需据此修订

## 1. 判定标准（五问）

一个工具能搬进插件，必须全部满足：

1. **数据可自持**：数据能落在 `.knowbase/plugins/<id>/`（kb.store.*），不需要读别的模块的库
2. **不碰系统安全面**：不用 DPAPI、不注册全局快捷键、不开本地网络端口
3. **UI 可沙箱**：界面是普通网页（沙箱 iframe 可渲染），不依赖主进程悬浮窗
4. **跨模块集成可降级**：与博客总结、状态栏等宿主功能的联动，能走 `kb.events` 上报而不是直写
5. **导入导出走授权通道**：文件选择经宿主对话框（Gateway 转发），不直接碰 fs

## 2. 逐工具判定

| 工具 | 依赖能力 | 关键阻碍 | 判定 |
|---|---|---|---|
| 强密码生成器 | — | — | ✅ **已转市场插件（现状，非本次改造）**；v3 运行时就绪后作为首个迁移对象 |
| 体重追踪 | kb.store（多系列数据）+ Canvas 渲染 | 无 | ✅ 可插件化 |
| 网址导航 | kb.store + 文件导入（Netscape HTML）| 需补 `kb.ui.filePicker` | ✅ 可插件化 |
| 习惯打卡 + 远程监督 | kb.store + 定时提醒 + 白名单 webhook | 需补 `kb.notify` + `kb.net.restricted`；督学与打卡共数据，**合并为一个插件** | ⚠️ 可插件化，能力齐备后 |
| 番茄钟 | 状态栏常驻 + 计入周月总结 | 需补 `kb.ui.statusbar`；「计入总结」改为 kb.events 上报、宿主决定采纳——联动质量略降 | ⚠️ 可插件化，接受联动降级则做 |
| **密码本** | DPAPI 加密、全局快速填充悬浮窗（Ctrl+Alt+P）、剪贴板安全清除 | **系统安全面，三条全撞红线** | ❌ 永久内置 |
| **数据导出** | 跨全部模块数据 + 对话框授权路径 + 拖入还原 | 数据完整性兜底功能，插件崩溃不能影响备份 | ❌ 永久内置 |
| **设备传输 lanShare** | 主进程 HTTP 服务、端口绑定、二维码、附件目录 | 系统级网络能力 | ❌ 永久内置 |

## 3. v3 需新增的 Gateway 命名空间（本评估的产出之一）

| 命名空间 | 能力 | 使用方 | 约束 |
|---|---|---|---|
| `kb.ui.statusbar` | 注册状态栏片段 | 番茄钟 | 数量上限，宿主可禁用 |
| `kb.notify` | 系统通知 / 应用内提醒 | 习惯打卡 | 需 manifest 声明 + 安装确认 |
| `kb.net.restricted` | 仅向用户配置的白名单 URL 发 POST | 远程监督 | 域名安装时锁定，运行时不可改 |
| `kb.ui.filePicker` | 唤起宿主文件选择框（读回内容） | 网址导航导入 | 宿主对话框授权，插件不见路径 |

## 4. 试点顺序（建议并入 R7）

1. **V3-3 首试点：强密码生成器迁移到 v3 运行时**——它已是市场插件，功能零新增，纯粹验证「沙箱运行时 + Gateway 协议 + 安装链路」全链路，是最干净的迁移测试
2. **第二批：体重追踪 + 网址导航**——验证 kb.store 持久化 + filePicker
3. **第三批：习惯监督（打卡+督学）**——验证 kb.notify / kb.net.restricted 两个高危能力的设计
4. **第四批：番茄钟**——验证 kb.ui.statusbar，且此时周月总结的 events 上报机制应已定型

## 5. 工具箱模块的最终形态

迁移完成后工具箱收窄为两类：
- **内置工具**（密码本 / 数据导出 / 设备传输）——保留现有整页或侧栏视图
- **插件工具**——出现在插件模块的已装列表，可从命令面板/侧栏启动；工具箱不再承载它们

迁移是**复制不是切换**：插件版验证稳定后才从内置下线，期间数据用导入脚本从旧表搬进 `.knowbase/plugins/<id>/`（对接 R3 数据层推广的节奏，每搬一个工具就少一个 SQLite 表依赖）。

## 6. 风险

- 打卡/番茄钟搬走后，远程监督的 Webhook 推送与「每日汇总」原来在主进程定时触发——插件模式需要宿主提供**定时唤醒**（后台 Worker 通道 B 的调度能力），这是 v3 运行时的隐性前置
- 番茄钟状态栏是用户高频可见面，插件崩溃不能拖垮状态栏 → statusbar 片段必须做渲染隔离（独立 iframe）
